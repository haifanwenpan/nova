# 第 1 章 项目概览与规格

## 1.1 这是什么

`nova` 是一个 **H.264/AVC Baseline Profile 视频解码器**的完整 Verilog RTL 实现。

- **作者**：Ke Xu（徐科），香港中文大学，邮箱 `eexuke@yahoo.com`
- **发布**：OpenCores 开源硬件项目，2008-04-21 创建，2008-05-02 首次上传代码，最后一次提交 2009-02-10
- **许可**：作者保留版权（`Copyright (C) 2008 Ke Xu`），OpenCores 开放 IP 形式发布
- **规模**：`src/` 下共 **52 个 `.v` 文件，25,826 行**（不含 `sim/` 自建仿真环境）
- **分辨率**：固定 **QCIF 176×144**（11 列 × 9 行 = **99 个宏块**）

它是作者博士论文 *Power-efficient Design Methodology for Video Decoding*（2007）的**硅验证载体**。理解这一背景，就能看懂源码里几乎所有反直觉的取舍：

> 这个 IP 的核心目标**不是**“兼容全网所有 H.264 码流”，而是**“用最低功耗把 Baseline 解码跑在 0.18 µm 芯片上”**。
> Gray 码状态机、分层 leading-one 检测、查表替代除法、移位替代乘法、单端口 SRAM 五级去块流水、39 路门控时钟，以及硬连线的 SPS 解析器，都是这条主线上的产物。

## 1.2 关键指标（来自规格书 `doc/nova_spec.doc` Rev 0.1）

### 功能指标

| 项目 | 规格书宣称 | 源码核实备注 |
|---|---|---|
| Profile | H.264/AVC **Baseline** | 实际为 Baseline 子集（仅 `poc_type=0`、`slice_type=5/7`、单参考帧、无 SEI/AUD/VUI/防竞争字节，见 [第 10 章](10-兼容性陷阱与移植指南.md)） |
| 分辨率 | QCIF 176×144（固定） | `mb_num_h` 0..10、`mb_num_v` 0..8、`mb_num` 0..98 硬编码 |
| 帧率与频率 | 30 fps @ **1.5 MHz** | 300 帧 akiyo 实测均值 49,954 cycles/帧，`× 30 = 1.50 MHz`，完全吻合 |
| 去块滤波吞吐 | **204 cycles/MB** | 实测 `DF_duration` 固定 **209 cycles/MB**（204 + 5 拍流水填充/状态清零） |
| 宏块类型 | I16×16 / I4×4 / P16×16 / P16×8 / P8×16 / P8×8 / P8×8ref0 / P_skip / I_PCM | **注意**：`I_PCM` 在 `nova_defines.v` 虽有宏定义，但 FSM 与 `syntax_decoding.v` **均未接入**（见 [第 10 章 10.3](10-兼容性陷阱与移植指南.md)） |
| 不支持 | CABAC、B 帧、加权预测、FMO/ASO、8×8 变换、多 slice | 符合预期 |

### 实现指标（来自 `learn/doc_extract/nova_spec.txt`）

| 项目 | 数值 |
|---|---|
| 工艺 | 0.18 µm CMOS 1P6M，1.8 V core / 3.3 V IO |
| 面积与封装 | core 3.8×3.8 mm²（pad limited），含 pad 4.4×4.4 mm²，CQFP 208 |
| 逻辑规模 | **169K NAND2 等效门** |
| 片上存储 | 规格书标称 **2.5K byte SRAM**（精确核实：5 块 SRAM = **2,656 B ≈ 2.59 KiB**，另加 8 个寄存器堆 RF = **1,480 bit = 185 B**，见 [第 8 章](08-存储组织与时钟门控.md)） |
| 实测功耗 | **293 µW @ 1.0 V**，973 µW @ 1.8 V（QCIF@30fps） |
| FPGA 综合 | Virtex-4 `xc4vlx200-10ff1513`：18,377 slices（20%），32,711 个 4-input LUT（18%） |
| 时钟范围 | 单时钟全同步（50/50 占空比），整片标称 **1 ~ 10 MHz**（独立 DF 最高 200 MHz） |

> **293 µW 是什么概念？** 一颗普通的 CR2032 纽扣电池（约 220 mAh @ 3V ≈ 660 mWh）理论上可以供它连续解码 QCIF 视频约 **94 天**。

## 1.3 支撑论文与 RTL 模块对应关系

这个 IP 的设计技巧分散发表在 8 篇学术论文里（规格书 Appendix A/B）。**每一篇论文都能直接对到具体的 `.v` 文件**：

| 论文 | 对应 RTL 文件 | 核心技术 |
|---|---|---|
| TCSVT 2008, 18(3):363-374<br>*A 5-stage Pipeline, 204 Cycles/MB, Single-port SRAM Based Deblocking Filter* | `DF_pipeline.v`、`DF_mem_ctrl.v`、`DF_reg_ctrl.v` | 5 级流水、2-row 混合滤波序、单端口 SRAM |
| TVLSI 2008, 16(3):302-313<br>*A Power-efficient and Self-adaptive Prediction Engine* | `Intra_pred_*.v`、`Inter_pred_*.v`、`hybrid_pipeline_ctrl.v` | 混合自适应流水、1×4 列并行 PE、Plane 种子法、13×13 参考滑窗 |
| TCAS-II 2007, 54(11):984-988<br>*Power Efficient VLSI Realization of Complex FSM for Bitstream Parsing* | `BitStream_parser_FSM_gating.v`、`nova_defines.v` | **Gray 码层次状态机** + 细粒度时钟门控 |
| EURASIP JES 2007<br>*Priority-based Heading One Detector* | `heading_one_detector.v` | **2 / 4 / 10 分层优先编码器**（利用前导零分布省电） |
| ISLPED 2007, 256-261<br>*Low-power H.264/AVC Baseline Decoder for Portable Applications* | 全局架构与 `*_gclk_gen.v` | 系统级低功耗与 39 路锁存器时钟门控 |
| ESSCIRC 2006, 162-165<br>*A Low-power BitStream Controller* | `BitStream_controller.v` | 位流解析器低功耗架构 |
| ISCAS 2006, 5339-5342<br>*Power-efficient VLSI Implementation of BitStream Parsing* | `BitStream_buffer.v`、`pc_decoding.v` | 128-bit 环形桶形缓冲 + 7-bit 指针推进 |
| PhD Thesis 2007<br>*Power-efficient Design Methodology for Video Decoding* | 全部 | 方法论总纲 |

> **阅读建议**：本机没有这些论文 PDF，但好在源码注释非常完整（多数文件头都有 `// Description` 和 `// Revise log`）。这套文档就是从 RTL 逐行反推出来的“带代码注解版论文”。

## 1.5 代码风格与编写演进

### 文件头与开发时间线

几乎每个模块顶部都有 `Generated` 日期，还原了作者当年自底向上的开发顺序：

| 日期 | 模块 | 意义 |
|---|---|---|
| 2005-05-16 ~ 06-12 | `BitStream_buffer.v` → `nC_decoding.v` → `exp_golomb` → `cavlc_decoder.v` | 先攻克最复杂的位流解析与 CAVLC |
| 2005-06-18 | `IQIT.v` | 紧接着做反量化与反变换 |
| 2005-09-25 | `Intra_pred_*.v` | 帧内预测引擎 |
| 2005-10-17 ~ 10-25 | `Inter_pred_*.v` | 帧间预测与 13×13 滑窗 |
| 2005-11-27 | `DF_*.v` | 去块滤波（依赖前段全部输出，最后写） |
| 2006-02-25 | `nova.v` | 顶层集成 |
| 2008-04-20 | `nova_defines.v` | 上传 OpenCores 前整理全局宏 |

### 常见命名约定（读代码前先混个眼熟）

| 命名模式 | 含义 | 典型例子 |
|---|---|---|
| `_s` | FSM 状态名 | `frame_num_s`、`mb_type_s` |
| `_MR` / `_TD` / `_PRE` / `_FIR` / `_MW` | 去块滤波的 5 个流水级后缀 | `bs_curr_PRE`、`p0_MW` |
| `_ena` / `l_xxx_ena` / `gclk_xxx` | 门控使能 / 低电平锁存后使能 / 门控时钟 | `parser_ena` → `l_parser_ena` → `gclk_parser` |
| `mbAddrA / B / C / D` | H.264 邻居宏块约定（**A=左、B=上、C=右上、D=左上**） | `Intra_mbAddrB_RAM`、`mvx_mbAddrC_RF` |
| `IsXxx` / `is_xxx` | 1-bit 布尔条件标志 | `IsHadamard`、`IsInterLuma`、`Is_V_jfqik` |
| `end_of_xxx` / `trigger_xxx` | 模块间握手完成脉冲 / 启动脉冲 | `end_of_MB_DEC`、`trigger_CAVLC` |

### 老代码的新工具链兼容性

源码写于 2005–2008 年（Verilog-2001 风格），在现代 `iverilog 12.0` 下只有两类小问题：
1. 拼接运算里写了无位宽整数 `+ 1`（`pc_decoding.v:195-196`、`Intra_pred_pipeline.v:325`），`iverilog` 严格报 `indefinite width`，改成 `+ 4'd1` 即可；
2. `Beha_BitStream_ram.v:30` 硬编码了作者的 Windows 路径 `D:/nova_opencores/...`。

`sim/scripts/setup_rtl.sh` 会自动把 `src/*.v` 复制到 `sim/rtl/` 并打好这 3 处补丁，**永远不要直接修改 `src/`**。

## 1.6 建议学习路线

不要一上来就顺着字母顺序读 52 个文件，按**“先跑起来 → 按数据流逐段精读 → 配合仿真和波形验证”**的节奏最省力：

1. **第 1 步（建概念）**：精读 [第 0 章](00-H.264基础.md) + [第 2 章](02-系统架构与顶层接口.md)，对照 `nova_defines.v` 和 `nova.v` 画出全局框图；
2. **第 2 步（先跑通）**：按 [第 9 章](09-仿真环境与ffmpeg对比.md) 跑一遍 `./scripts/run_regression.sh -n 3`，亲眼看到 iverilog 编译、解码、与 ffmpeg 逐像素比对 PASS；
3. **第 3 步（位流侧）**：读 [第 3 章](03-位流解析链路.md)，按顺序看 `BitStream_buffer` → `heading_one_detector` → `exp_golomb_decoding` → `pc_decoding` → `BitStream_parser_FSM_gating` → `cavlc_decoder`；
4. **第 4 步（重建侧）**：按 [第 4](04-残差重建-IQIT.md) → [5](05-帧内预测.md) → [6](06-帧间预测与运动补偿.md) → [7](07-去块滤波.md) → [8](08-存储组织与时钟门控.md) 章逐个模块精读，每读完一章去 [第 11 章](11-动手实验.md) 改一行代码或加探针验证直觉；
5. **第 5 步（排错与改造）**：结合 [第 10 章](10-兼容性陷阱与移植指南.md) 理解边界限制，用 [第 12 章](12-波形调试与wave-mcp.md) 查逐拍波形。
