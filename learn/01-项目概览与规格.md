# 第 1 章 项目概览与规格

## 1.1 这是什么

`nova` 是一个 **H.264/AVC Baseline Profile 视频解码器**的完整 RTL 实现。

- **作者**：Ke Xu（徐科），香港中文大学，邮箱 `eexuke@yahoo.com`
- **发布**：OpenCores 项目，2008-04-21 创建，2008-05-02 首次上传代码，最后一次提交 2009-02-10
- **许可**：作者保留版权（`Copyright (C) 2008 Ke Xu`），OpenCores 上以开放 IP 形式发布
- **规模**：52 个 Verilog 文件，**25826 行**（`wc -l src/*.v`）
- **分辨率**：固定 QCIF **176×144**（11×9 = **99 个宏块**）

它是作者博士论文 *Power-efficient Design Methodology for Video Decoding*（2007）的
**硅验证载体**。这句话很重要——理解了它，你就理解了整个设计的取舍逻辑：

> 这个 IP 的目标**不是**"支持 H.264 的所有特性"，而是
> **"用最少的功耗解出一个 Baseline 子集"**。
> 每一个看起来"奇怪"的实现（Gray 码状态机、查表代替除法、移位代替乘法、
> 硬连线的 SPS 字段序列）都是这条主线上的必然选择。

## 1.2 关键指标（来自规格书 nova_spec.doc Rev 0.1）

### 功能指标

| 项目 | 数值 |
|---|---|
| Profile | H.264/AVC **Baseline** |
| 分辨率 | QCIF 176×144（固定） |
| 帧率 | 30 fps |
| 工作频率 | **1.5 MHz**（QCIF@30fps 只需这么点） |
| 吞吐 | **204 cycles/MB**（去块滤波），实测 209 |
| 编码工具 | I16×16 / I4×4 / P16×16 / P16×8 / P8×16 / P8×8 / P8×8ref0 / P_skip / I_PCM |
| 不支持 | CABAC、B 帧、加权预测、FMO/ASO、8×8 变换、多 slice |

### 实现指标

| 项目 | 数值 |
|---|---|
| 工艺 | 0.18 µm CMOS 1P6M，1.8V core / 3.3V IO |
| 面积 | core 3.8×3.8 mm²（pad limited），含 pad 4.4×4.4 mm²，CQFP 208 |
| 门数 | **169K NAND2 等效门** |
| 片上 SRAM | **2.5 K byte** |
| 功耗 | **293 µW @ 1.0V**，973 µW @ 1.8V（QCIF@30fps） |
| FPGA | Virtex-4 xc4vlx200-10ff1513：18377 slices（20%），32711 个 4-input LUT（18%） |
| 时钟 | 单时钟全同步，占空比 50/50，标称 Max 10 MHz / Min 1 MHz |

> **293 µW 是什么概念？** 一颗 CR2032 纽扣电池（约 220 mAh @ 3V ≈ 660 mWh）
> 可以供它连续解码 QCIF 视频 **约 2250 小时，即 94 天**。
> 这就是"低功耗视频解码"这个课题的意义所在。

## 1.3 支撑论文

这个 IP 的技术点分散发表在 8 篇论文里（规格书 Appendix A/B 列出）。**每篇论文对应 RTL 里的一个模块**：

| 论文 | 对应 RTL 模块 | 关键技术 |
|---|---|---|
| TCSVT 2008, 18(3):363-374<br>*A 5-stage Pipeline, 204 Cycles/MB, Single-port SRAM Based Deblocking Filter* | `DF_pipeline.v`<br>`DF_mem_ctrl.v` | 5 级流水、单端口 SRAM 实现双向滤波 |
| TVLSI 2008, 16(3):302-313<br>*A Power-efficient and Self-adaptive Prediction Engine* | `Intra_pred_*.v`<br>`Inter_pred_*.v`<br>`hybrid_pipeline_ctrl.v` | 混合自适应流水线、1×4 列并行、种子法 |
| TCAS-II 2007, 54(11):984-988<br>*Power Efficient VLSI Realization of Complex FSM for Bitstream Parsing* | `BitStream_parser_FSM_gating.v`<br>`nova_defines.v`（状态编码） | **Gray 码状态机** |
| EURASIP JES 2007<br>*Priority-based Heading One Detector* | `heading_one_detector.v` | **分层 2/4/10 分组** leading-one 检测 |
| ISLPED 2007, 256-261<br>*Low-power H.264/AVC Baseline Decoder for Portable Applications* | 整体 | 系统级低功耗方法 |
| ESSCIRC 2006, 162-165<br>*A Low-power BitStream Controller* | `BitStream_controller.v` | 位流控制器低功耗 |
| ISCAS 2006, 5339-5342<br>*Power-efficient VLSI Implementation of BitStream Parsing* | `BitStream_buffer.v`<br>`pc_decoding.v` | 桶形移位 + 位指针 |
| PhD Thesis 2007<br>*Power-efficient Design Methodology for Video Decoding* | 全部 | 方法论总纲 |

> **本机没有这些 PDF。** 想深入某个技术点，最可靠的办法是**直接读 RTL**——
> 好消息是这个 IP 的 RTL 注释质量相当高，几乎每个模块头部都有 `// Description` 段落
> 说明设计意图。本文档的写法就是"从 RTL 反推论文"。

### `src/` 里没有的东西

- **没有 testbench 的顶层**（`nova_tb.v` 有，但它依赖 `ext_frame_RAM*_wrapper.v`
  里的硬编码 Windows 绝对路径，且用 `$fdisplay` 写日志文件而不是写标准 YUV）
- **没有综合脚本 / 约束文件 / 后端脚本**
- **没有 Makefile、没有仿真脚本**（`bin2hex.pl` 是唯一的辅助脚本，且路径写死）
- **`src/target/` 下有两个空目录** `global-logging/`、`task-temp-directory/`
  —— 这是某个综合流程（很可能是 Synopsys 的流程模板）留下的痕迹，与本设计无关

> 这意味着：**这个 IP 交付的是"能综合的 RTL"，不是"能直接跑的工程"。**
> 想跑起来必须自己补 testbench 和脚本 —— 这正是本文档第 9 章做的事。

## 1.5 代码风格观察

读源码前先了解风格，能省很多时间：

### 文件头统一格式

```verilog
//--------------------------------------------------------------------------------------------------
// Design    : nova
// Author(s) : Ke Xu
// Email     : eexuke@yahoo.com
// File      : IQIT.v
// Generated : June 18, 2005
// Copyright (C) 2008 Ke Xu
//-------------------------------------------------------------------------------------------------
// Description
// Decoding the residual information
// 1.The res_mb_bypass | DConly | allzero signals should be decoded first
// ...
//-------------------------------------------------------------------------------------------------
// Revise log
// 1.March 27,2006
// DC_output: 0 ~ 15:for luma DC, 0 ~ 3:for Chroma Cb DC, 4 ~ 7:for Chroma Cr DC
```

**`Generated` 日期是宝藏**——它记录了模块的编写顺序，能反映设计演进：

| 日期 | 模块 | 推断 |
|---|---|---|
| 2005-05-18 | `nC_decoding.v` | CAVLC 的 nC 推导最先做（最难的部分） |
| 2005-06-12 | `cavlc_decoder.v` | CAVLC 整体框架 |
| 2005-06-18 | `IQIT.v` | 残差重建 |
| 2005-09-25 | `Intra_pred_reg_ctrl.v` | 帧内预测 |
| 2005-10-17 | `Inter_pred_reg_ctrl.v` | 帧间预测 |
| 2005-10-25 | `Inter_pred_sliding_window.v` | 帧间滑窗优化 |
| 2005-11-27 | `DF_mem_ctrl.v` / `DF_reg_ctrl.v` | 去块滤波（最后做） |
| 2006-02-25 | `nova.v` | 顶层集成 |

即：**先做熵解码 → 再做重建 → 再做预测 → 最后做去块滤波 → 最后集成**。
这是很自然的顺序，因为去块滤波依赖前面所有环节的输出。

### 包含头文件

每个文件都是这两行：

```verilog
// synopsys translate_off
`include "timescale.v"
// synopsys translate_on
`include "nova_defines.v"
```

`translate_off/on` 让综合工具忽略 timescale（timescale 只对仿真有意义）。

### 命名约定

| 后缀/前缀 | 含义 | 例子 |
|---|---|---|
| `_s` | FSM 状态名 | `frame_num_s`、`mb_type_s` |
| `_MR` `_TD` `_PRE` `_FIR` `_MW` | 去块滤波的 5 个流水级 | `bs_curr_FIR`、`p0_MW` |
| `_ena` / `l_xxx_ena` | 门控时钟的使能 / 负沿锁存的使能 | `l_parser_ena` |
| `gclk_xxx` | 门控后的时钟 | `gclk_parser`、`gclk_DF` |
| `mbAddrA/B/C/D` | H.264 的相邻宏块位置（左/上/右上/左上） | `Intra_mbAddrB_RAM` |
| `_mbAddrB_RF` | 存在寄存器堆里（跨 MB 传递） | `LumaLevel_mbAddrB_RF` |
| `IsXxx` / `is_xxx` | 条件标志 | `IsInterLuma`、`Is_skip_run_entry` |
| `end_of_xxx` | 某个处理单元完成 | `end_of_MB_DEC`、`end_of_one_blk4x4_sum` |

### 位宽与拼接

代码里大量使用 `{a, b}` 拼接做位宽扩展，而且**经常依赖 Verilog 的隐式规则**。
这正是 iverilog 12.0 编译报错的原因（见第 9 章）：

```verilog
// 原始代码（iverilog 报 "indefinite width"）
pc <= {{pc_reg[6:3] + 1}, 3'b0};

// 修复后（显式指定 4 位）
pc <= {{pc_reg[6:3] + 4'd1}, 3'b0};
```

原因是 Verilog-2001 里 `+` 的结果位宽取操作数的最大位宽，而 `1` 是无位宽的
整数常量（32 位有符号），拼接一个 32 位表达式到 7 位向量里，iverilog 认为宽度不确定。
**这是老代码在新工具链上的典型问题，功能上完全无害。**

## 1.6 建议的阅读顺序

不要从 `nova.v` 开始往下读——顶层只是连线，读完什么也记不住。
建议按**数据流**读，每读一个模块就在纸上画一下它的输入输出：

```
第 1 遍：骨架（建立全局图景）
  nova_defines.v          ← 先读宏，知道状态名和常量
  nova.v                  ← 只看端口和两个子模块的例化
  BitStream_controller.v  ← 只看端口列表，不进去
  reconstruction.v        ← 只看 8 个子模块的例化

第 2 遍：位流解析链路（数据从哪来）
  BitStream_buffer.v      ← 128 bit 桶形缓冲，怎么按 pc 取 16 bit
  heading_one_detector.v  ← leading-one 检测，分层比较
  exp_golomb_decoding.v   ← ue/se/te 三种码
  pc_decoding.v           ← 位指针推进
  syntax_decoding.v       ← 语法元素装配
  BitStream_parser_FSM_gating.v ← 大状态机（638 行，最枯燥但最重要）
  cavlc_decoder.v + 7 个子模块 ← CAVLC 熵解码

第 3 遍：重建链路（数据到哪去）
  IQIT.v                  ← 反量化 + 反变换（蝶形，无乘法）
  Intra_pred_PE.v         ← 帧内预测的 4 个 PE
  Intra_pred_pipeline.v   ← 种子法
  Inter_pred_LPE.v        ← 6-tap 插值（无乘法）
  Inter_pred_CPE.v        ← 色度双线性
  Inter_pred_sliding_window.v ← 参考像素滑窗
  sum.v                   ← 残差 + 预测 + 饱和
  DF_pipeline.v           ← 去块滤波 5 级流水（860 行，最精巧）

第 4 遍：控制与存储（为什么能跑这么快/这么省）
  hybrid_pipeline_ctrl.v  ← 混合流水线的调度
  bitstream_gclk_gen.v    ← 位流侧时钟门控
  rec_gclk_gen.v          ← 重建侧时钟门控
  DF_mem_ctrl.v           ← 帧存地址计算
  ext_RAM_ctrl.v          ← 双帧存乒乓
```

**每一遍都配合仿真**。第 9 章教的探针脚本能打印任意内部信号——
看波形不如看打印，iverilog 的 `$display` 比波形窗口高效得多。
