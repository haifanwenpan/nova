# 第 5 章 帧内预测

帧内预测（Intra Prediction）用**当前帧已经重建好的相邻像素**来预测当前块。它是 `nova` 的 **TVLSI 2008 论文**（*A Power-efficient and Self-adaptive Prediction Engine*）的核心之一，由 4 个文件（3,539 行）实现：

| 文件 | 行数 | 职责 |
|---|---|---|
| `Intra_pred_top.v` | 333 | 顶层装配 + 例化 `Intra_mbAddrB_RAM`（88×32-bit SRAM） |
| `Intra_pred_pipeline.v` | 743 | Preload / Precompute / Calculate 三阶段控制 + Plane 梯度与种子预计算 |
| `Intra_pred_reg_ctrl.v` | 838 | 维护 13 个邻居窗口（`mbAddrA/B/C/D` 寄存器）+ 3 个 Plane 种子寄存器 |
| `Intra_pred_PE.v` | 1625 | 4 个 1×4 列并行多功能 PE，统一支持 I4×4（9 模式）、I16×16（4 模式）、Chroma（4 模式） |

> 📖 **概念预热**：帧内预测直觉、Intra 4×4 / 16×16 / 色度模式区别、模式号 `min(A, B)` 预测 —— 见 [第 0 章 0.5 节](00-H.264基础.md)。

## 5.1 13 个参考像素与 `Intra_mbAddrA/B/C/D` 窗口

H.264 对一个 4×4 块做帧内预测时，最多需要周围 **13 个已重建像素**（1 左上 + 4 正上 + 4 右上 + 4 正左）：

```text
   左上(1)    正上(4)                右上(4)
     D    │ B0   B1   B2   B3   │ C0   C1   C2   C3
   ───────┼─────────────────────┘
   A0     │ p00  p01  p02  p03      ← 待预测的 4×4 块（16 个像素）
   A1     │ p10  p11  p12  p13
   A2     │ p20  p21  p22  p23
   A3     │ p30  p31  p32  p33
  正左(4)
```

在 `src/Intra_pred_reg_ctrl.v:83-109` 中，这 13 个输入窗口全部由**触发器寄存器**（不是 RF！）供给：

| 窗口信号 | 对应位置 | 数据来源（`Intra_pred_reg_ctrl.v`） |
|---|---|---|
| `Intra_mbAddrA_window0..3` | 左 4 像素 `A0..A3` | 来自 `Intra_mbAddrA_{luma,Cb,Cr}_reg`（16+8+8 = 32 个 8-bit FF），每次 `sum.v` 算完一块就用 `{sum_right_column_reg[23:0], blk4x4_sum_PE3_out}` 更新 |
| `Intra_mbAddrB_window0..3` | 上 4 像素 `B0..B3` | 来自 `Intra_mbAddrB_reg0..15`（16 个 8-bit FF）；MB 顶行从片上 **`Intra_mbAddrB_RAM`**（88×32-bit SRAM）预加载，MB 内部由 `sum.v` 底行输出 `blk4x4_sum_PE0..3_out` 更新 |
| `Intra_mbAddrC_window0..3` | 右上 4 像素 `C0..C3` | 顶行块 `0,1,4,5` 从 `Intra_mbAddrC_reg0..3`（预加载自 `Intra_mbAddrB_RAM` 中**上邻/右上邻 MB 的底边一行**）；内部块直接取 `Intra_mbAddrB_reg`；不可用时（如块 3,7,11,13,15 或最右列块 5）复制 `B3` |
| `Intra_mbAddrD_window` | 左上角 1 像素 `D` | 来自 `Intra_mbAddrD_reg0..4` 与 `Intra_mbAddrD_LeftMB_{luma,Cb,Cr}_reg`（共 8 个 8-bit FF） |

**为什么 `Intra_mbAddrB_RAM` 是 88 × 32-bit？**
QCIF 画面宽 176 像素（4 像素/word = 44 word），Cb 和 Cr 各宽 88 像素（各 22 word）：
`44 (Y 底边一行) + 22 (Cb 底边一行) + 22 (Cr 底边一行) = 88 word`（`Intra_pred_pipeline.v:311-386`）。

## 5.2 三类预测模式编码（对照 `nova_defines.v:232-250`）

> ⚠️ **核实提醒**：`nova` 的帧内预测模式**全部采用 H.264 标准二进制编号，并没有使用 Gray 码**（不要与第 3 章的 Gray 码状态机混淆）：

- **Intra 4×4（亮度 9 种，`nova_defines.v:232-240`）**：
  - `4'b0000` (0) `Vertical`、`4'b0001` (1) `Horizontal`、`4'b0010` (2) `DC`
  - `4'b0011` (3) `Diagonal_Down_Left`（45°）、`4'b0100` (4) `Diagonal_Down_Right`（45°）
  - `4'b0101` (5) `Vertical_Right`（26.6°）、`4'b0110` (6) `Horizontal_Down`（26.6°）
  - `4'b0111` (7) `Vertical_Left`（26.6°）、`4'b1000` (8) `Horizontal_Up`（26.6°）
  *(注：角度 5/6/7/8 的斜率是 `1:2` 或 `2:1`，即 $\arctan(1/2) \approx 26.6^\circ$，所以只需要 `(a+b+1)>>1` 和 `(a+2b+c+2)>>2` 两种极简加权！)*
- **Intra 16×16（亮度 4 种，`nova_defines.v:242-245`）**：`00 = Vertical`，`01 = Horizontal`，`10 = DC`，`11 = Plane`。
- **Intra Chroma（色度 8×8，4 种，`nova_defines.v:247-250`）**：**`00 = DC`**，`01 = Horizontal`，`10 = Vertical`，`11 = Plane`（注意色度 `0` 是 DC，顺序和 16×16 不同！）。

## 5.3 1×4 列并行与多功能 PE 结构（`Intra_pred_PE.v`）

### 1. 为什么选“1×4 列并行（每拍算 1 列 4 个像素）”？

`blk4x4_intra_calculate_counter` 从 `4 → 3 → 2 → 1` 倒数 **4 拍**，每拍 4 个 PE（`PE0..PE3`）同时算出**同一列的 4 个像素**（`sum.v:138-147`）：
- `cnt = 4`（第 0 列 `x=0`）：`PE0..PE3` → 写入 `blk4x4_pred_output{0, 4, 8, 12}`
- `cnt = 3`（第 1 列 `x=1`）：`PE0..PE3` → 写入 `blk4x4_pred_output{1, 5, 9, 13}`
- `cnt = 2`（第 2 列 `x=2`）：`PE0..PE3` → 写入 `blk4x4_pred_output{2, 6, 10, 14}`
- `cnt = 1`（第 3 列 `x=3`）：`PE0..PE3` → 写入 `blk4x4_pred_output{3, 7, 11, 15}`

**选按列推进而不是按行推进，有两个硬核硬件原因**：
1. **斜向预测的跨列像素复用**：在 45° / 26.6° 模式（如 DDL、DDR、VR、HD、VL、HU）里，同一条斜线上的多个像素预测公式完全相同！例如 DDR 模式里 `(1,1)` 等于 `(0,0)`、`(2,1)` 等于 `(1,0)`。按列计算时，第 `x` 列已经算好的预测像素暂存在 `sum.v` 的 `blk4x4_pred_output` 中，第 `x+1` 列直接通过 `full_bypass = 1` 复用上一列算好的像素，**连加法器都不用动**！
   - 这也解释了为什么 `Intra_pred_top.v:25-28` 的**输入端口**里只有 12 个预测像素 **`blk4x4_pred_output{0,1,2, 4,5,6, 8,9,10, 12,13,14}`** 而**缺了 `3, 7, 11, 15`** —— 这 12 个是当前 4×4 块的**前 3 列像素**（来自 `sum.v`），第 3 列（`3, 7, 11, 15`）在最后一拍 `cnt == 1` 才算出来，没有后续列会复用它们！
2. **Plane 模式的水平增量累加**：4 个 PE 各自把当前值存在内部寄存器 `PE0..3_out_reg` 里，每前进 1 列只需 `PEk_out_reg + b`，天然契合按列推进！

### 2. 多功能 PE 的真实电路（`Intra_pred_PE.v:1588-1626`）

4 个 PE（`PE0..PE3`）例化自同一个 `PE` 子模块 —— 它接收 **4 个 16-bit 输入**，靠 4 个控制位通吃全部 17 种模式（4×4 的 9 种 + 16×16 的 4 种 + 色度的 4 种）：

```verilog
// Intra_pred_PE.v:1588-1626（精炼注释版）
module PE (clk, reset_n, IsShift, IsStore, IsClip, full_bypass,
           round_value, shift_len, in0, in1, in2, in3, PE_out_reg, PE_out, sum_out);
    input [15:0] in0, in1, in2, in3;  // 4 个 16-bit 输入（既可接 8-bit 像素，也可接 16-bit Plane 种子/DC 累加和！）

    // 核心加法树：3 个 16-bit 加法器
    assign sum1    = in0 + in1;
    assign sum2    = (IsShift == 1'b1) ? {in2[14:0], 1'b0} : (in2 + in3); // IsShift=1 实现 2*in2！
    assign sum_out = sum1 + sum2;                                         // = in0+in1+2*in2 或 in0+in1+in2+in3

    // 可选锁存中间和（用于 DC 跨拍累加、Plane 水平 +b 累加）
    always @ (posedge clk)
        if (!reset_n)      PE_out_reg <= 0;
        else if (IsStore)  PE_out_reg <= sum_out;

    // 舍入 + 右移 + 可选裁剪到 [0, 255] + 可选全旁路
    assign round_out = (sum_out + {11'b0, round_value}) >> shift_len;
    assign clip_out  = (IsClip == 1'b0) ? round_out[7:0] :
                       ((round_out[15] == 1'b1) ? 8'd0 :
                       ((round_out[14:8] != 0)  ? 8'd255 : round_out[7:0]));
    assign PE_out    = (full_bypass == 1'b1) ? in0[7:0] : clip_out;
endmodule
```

**看这个 PE 多能打**：
- **Vertical / Horizontal / 斜向像素复用**：设 `full_bypass = 1`，直接透传 `in0[7:0]`；
- **`(a + 2b + c + 2) >> 2`**（斜向 3 抽头）：设 `in0=a, in1=c, in2=b, IsShift=1, round_value=2, shift_len=2`；
- **`(a + b + 1) >> 1`**（斜向 2 抽头）：设 `in0=a, in1=b, in2=0, in3=0, IsShift=0, round_value=1, shift_len=1`；
- **DC 模式**（如 4×4 DC）：`cnt=4` 时 PE0 算 `B0+B1+B2+B3` 存进 `PE0_out_reg`，PE1 算 `A0+A1+A2+A3` 存进 `PE1_out_reg`；`cnt=3` 时 PE0 把两份加起来 `(sumB + sumA + 4) >> 3`，在 `sum.v:106-120` 一次广播到全部 16 个像素！
- **Plane 模式**：`in0=seed / PE_out_reg, in1=b/c, round_value=16, shift_len=5, IsStore=1, IsClip=1`！

## 5.4 “种子法”零乘法实现 Plane 模式（TVLSI 论文核心）

H.264 8.3.3.4 / 8.3.4.4 规定的 Plane 模式公式（**注意没有额外加邻像素**）：

```text
Intra16×16 亮度： pred(x, y) = Clip1( (a + b·(x − 7) + c·(y − 7) + 16) >> 5 ),   x, y ∈ 0..15
  其中 a = 16·(A[15] + B[15])
       H = Σ_{x'=0..7} (x'+1)·(B[8+x'] − B[6−x'])，  b = (5·H + 32) >> 6
       V = Σ_{y'=0..7} (y'+1)·(A[8+y'] − A[6−y'])，  c = (5·V + 32) >> 6

Intra Chroma 色度：pred(x, y) = Clip1( (a + b·(x − 3) + c·(y − 3) + 16) >> 5 ),   x, y ∈ 0..7
  其中 a = 16·(A[7] + B[7])
       H = Σ_{x'=0..3} (x'+1)·(B[4+x'] − B[2−x'])，  b = (17·H + 16) >> 5
       V = Σ_{y'=0..3} (y'+1)·(A[4+y'] − A[2−y'])，  c = (17·V + 16) >> 5
```

### 第 1 步：Precomputation 阶段无乘法算 `H, V, a, b, c, main_seed`（`Intra_pred_pipeline.v:389-717`）

这一步**整个宏块（或整个色度平面）只跑一次**，用 `blk4x4_intra_precompute_counter` 调度（亮度 **11 拍**，色度 **7 拍**）：
1. **`plane_HV_precomputation`（`:662-695`）**：亮度用 4 拍算 `V`（每拍 2 项：`(×1,×3)`, `(×2,×5)`, `(×4,×6)`, `(×8,×7)` 全用移位加减，**0 乘法器**），第 5 拍算 `c`；再用 4 拍算 `H`，第 10 拍同时算 `a` 和 `b`；第 11 拍算 `main_seed`！
2. **`plane_bc_precomputation`（`:644-660`）**：亮度用 `5·HV = (HV<<2) + HV`，色度用 `17·HV = (HV<<4) + HV`，同样 **0 乘法器**！
3. **`main_seed_precomputation`（`:697-717`）**：
   ```verilog
   // Luma (IsIntra16x16=1):  main_seed = a - 7*b - 8*c  （因为 7b = 8b - b，8c = c << 3）
   // Chroma (IsIntra16x16=0): main_seed = a - 3*b - 4*c （因为 3b = 4b - b，4c = c << 2）
   ```

### 第 2 步：为什么是 `−8c` 而不是 `−7c`？看懂二级种子接力！

展开亮度公式：`a + b(x−7) + c(y−7) = (a − 7b − 8c) + b·x + c·(y + 1)`。
把 **`main_seed = a − 7b − 8c`** 想象成虚拟坐标 `(x = 0, y = -1)` 处的种子，存入 **`seed_0`**（`Intra_pred_reg_ctrl.v:805-835`）：

```text
宏块内 16 个 4×4 块按【双 Z 序】解码，看三颗种子 seed_0 / seed_1 / seed_2 怎么接力：

   左半 8×8 列 (x=0..7)                右半 8×8 列 (x=8..15)
 ┌────────────┬────────────┐         ┌────────────┬────────────┐
 │ blk 0      │ blk 1      │         │ blk 4      │ blk 5      │
 │ cnt=4:     │ cnt=4..1:  │─seed_1─▶│ cnt=4:     │ cnt=4..1:  │
 │ PE0: s0+c  │ 沿 PE_reg  │ (x=7,y=0)│ PE0: s1+b  │ 沿 PE_reg  │
 │ PE1: s0+2c │ 继续 +b！  │         │ PE1: s1+b+c│ 继续 +b！  │
 │ PE2: s0+3c │            │         │ PE2: s1+b+2c│           │
 │ PE3: s0+4c │            │         │ PE3: s1+b+3c│           │
 │  └─▶ 更新 s0!           │         │            │            │
 ├────────────┼────────────┤         ├────────────┼────────────┤
 │ blk 2      │ blk 3      │─seed_2─▶│ blk 6      │ blk 7      │
 │ (重复 blk0)│            │ (x=7,y=4)│ (用 seed_2)│            │
 └────────────┴────────────┘         └────────────┴────────────┘
  blk 8, 9, 10, 11 与 blk 12, 13, 14, 15 走完全相同的接力流程！
```

**一眼看懂 `−8c` 的天才之处**：
- 在 `blk 0` 的第 0 列（`cnt == 4`），4 个 PE 用 `seed_0` 分别算 `+c, +2c, +3c, +4c`（正好对应 `y = 0, 1, 2, 3`），同时把 `PE3` 的输出（即 `y = 3` 的值）存回 `seed_0`！
- 于是到了下一行 `blk 2`（`y = 4..7`）时，`seed_0` 恰好站在 `y = 3`，4 个 PE **完全不用改公式**，继续算 `seed_0 + c, +2c, +3c, +4c` 就是 `y = 4, 5, 6, 7`！
- 在同一个 8×8 内部从左块进右块（如 `blk 0 → blk 1`），`PE0..3_out_reg` 里已经存着第 3 列（`x = 3`）的值，进入 `blk 1` 的 `cnt = 4` 直接 `+b` 就是 `x = 4`，无缝衔接！
- 当 `blk 1` 算完最后一列（`x = 7, y = 0`），把 `PE0` 的和存进 `seed_1`；`blk 3` 算完（`x = 7, y = 4`）存进 `seed_2`。等到双 Z 序跳去解右上 8×8 的 `blk 4` 和 `blk 6` 时，分别从 `seed_1` 和 `seed_2` 接棒继续往右长！

**全流程 512 次乘法 → 0 次乘法，每个像素只需 1 次加法！**

## 5.5 三阶段调度、双 Z 块序与边界可用性

### 1. 三阶段计数器（`Intra_pred_pipeline.v`）

每个 4×4 帧内块依次走过最多 3 个计数器：
1. **Preload**（`blk4x4_intra_preload_counter`，`:131-165`）：仅在需要读片上 SRAM `Intra_mbAddrB_RAM` 时启动（如 MB 顶行块 `0, 1, 4, 5` 及色度顶行块），把上邻/右上邻像素加载进 `Intra_mbAddrB_reg` / `Intra_mbAddrC_reg`；
2. **Precomputation**（`blk4x4_intra_precompute_counter`，`:168-183`）：**仅 Plane 模式**在第 0 块（亮度 `blk=0` 跑 11 拍，色度 `blk=16/20` 跑 7 拍）启动，其余所有模式为 0；
3. **Calculation**（`blk4x4_intra_calculate_counter`，`:185-235`）：`4 → 3 → 2 → 1 → 0`，4 个 PE 按列算出 16 个像素并交给 `sum.v`。

### 2. 双 Z 块序与边界可用性

- **处理顺序是双 Z 序（`blk4x4_rec_counter` 0..15）**，不是光栅序！例如 `Intra_pred_pipeline.v:114-119` 判断“块在 MB 左边”用的是 `0, 2, 8, 10`，判断“块在 MB 顶边”用的是 `0, 1, 4, 5`。
- **可用性信号**：`Intra_pred_pipeline.v:114-129` 同时维护三个可用性标志：
  - `mbAddrA_availability`：MB 非最左列（`mb_num_h != 0`）或当前 4×4 块在 MB 内部；
  - **`mbAddrB_availability`**（`:125`）：`mb_type_general[3] && mb_num_v != 0`（MB 非最顶行）；
  - `mbAddrC_availability`：右上参考像素是否可用（最顶行、最右列或双 Z 序下右上尚未解码的块如 `3, 7, 11, 13, 15` 时不可用，需复制 `B3`）。
- **关于 `constrained_intra_pred_flag`**：源码核实发现该标志在 `syntax_decoding.v:244` 解析后**只传给了 `Intra4x4_PredMode_decoding.v:100, 102`**（用于模式号预测），**并未传入 `reconstruction.v` / `Intra_pred_top.v`** —— 也就是像素级帧内预测默认 `constrained_intra_pred_flag == 0`。

## 5.6 本章小结：帧内预测的三大硬件创新

| 创新点 | 解决什么问题 | `nova` 具体实现 |
|---|---|---|
| **二级种子法（Plane）** | 16×16 Plane 朴素需要 512 次乘法 | 预计算 `main_seed = a − 7b − 8c` + `seed_0/1/2` 跨块接力 → **0 乘法器** |
| **1×4 列并行 + 4 输入多功能 PE** | 4×4 全并行面积太大，逐像素太慢 | 4 个 PE 并行算 1 列（4 拍/块），支持 17 种模式与跨列 `blk4x4_pred_output` 复用 |
| **片上寄存器 + 88×32 行缓存** | 跨 MB 访存开销大 | MB 内靠 FF 直接复用 `sum.v` 的底行与 `sum_right_column_reg[23:0]`，跨行只用 1 块 352 B SRAM |
