## 6.2 为什么参考像素缓存恰好是 13×13 = 169 个寄存器？

`Inter_pred_reg_ctrl.v:60-112` 例化了整颗芯片最大的一组寄存器阵：`Inter_ref_00_00` 到 `Inter_ref_12_12`，共 **13 × 13 = 169 字节（1,352 bit）**。

**13×13 的真正数学来源（彻底纠正误解）**：
1. 6-tap 滤波器在每个输出像素的左侧需要额外 2 个整数像素、右侧需要额外 3 个整数像素，总共多出 **`+5`** 个像素（垂直方向同理）；
2. 对于 **8×8 及以上**的大划分（16×16、16×8、8×16、8×8，`mv_below8x8_curr == 0`），`nova` 在该 8×8 象限的**第 1 个 4×4 块**（`blk4x4_rec_counter[1:0] == 2'b00`）时，一次性把整个 8×8 区域连同周围抽头全部预加载进 `Inter_ref`：
   ```text
   所需宽度 = 8 + 5 = 13 像素（偏移 -2 .. +10）
   所需高度 = 8 + 5 = 13 像素（偏移 -2 .. +10）
   ```
   随后的第 2、3、4 个 4×4 子块**直接复用这份 13×13 缓存，零额外帧存读取**，一举省掉 **3/4** 的外部访存！
3. 对于 **8×8 以下**的小划分（8×4、4×8、4×4，`mv_below8x8_curr == 1`），每个 4×4 块有独立 MV，只预加载 **`4 + 5 = 9 × 9`**（只用到 `Inter_ref_00..08 × 00..08`）。
4. 外部帧存一次吐 4 像素（32-bit），起点 `xInt_org_unclip[1:0]` 可能有 0..3 的字内偏移。**这个字内偏移在 `Inter_pred_reg_ctrl.v` 拆包写入 `Inter_ref` 时就已经被彻底剥离对齐了**，所以无论 MV 指向哪，`(xInt_org − 2, yInt_org − 2)` 永远稳稳落在 `Inter_ref_00_00`，8×8 的整数像素永远落在 `Inter_ref_02..09 × 02..09`！

## 6.3 滑动窗口重组：`Inter_pred_sliding_window.v`

`Inter_pred_sliding_window.v` 不需要知道 `xInt_org_unclip[1:0]`。它只根据当前 4×4 块在 8×8 内的象限 `Is_blk4x4_0..3`（基址偏移 `(0,0) / (+4,0) / (0,+4) / (+4,+4)`）、分数位置 `pos_FracL` 和列计数器，把 `Inter_ref_00_00..12_12` 分发到 5 组输出窗口：

| 输出窗口 | 尺寸 | 数据类型与用途 |
|---|---|---|
| `Inter_H_window_0_0 .. 5_8` | **6 × 9** | 9 组水平 6-tap 输入（每行 6 个 8-bit 整数像素，共 9 行）：其中第 `0,1,6,7,8` 行仅在 `j/f/q/i/k` 时激活，第 `2,3,4,5` 行在所有需水平滤波的位置激活 |
| `Inter_V_window_0 .. 8` | **1 × 9** | **9 个 8-bit 整数像素**（直接来自 `Inter_ref` 的某一列！用于 `h/d/n/e/g/p/r/i/k` 的整数垂直 6-tap；注意：**水平滤波后的 15-bit 中间值不走这里，而是存在 LPE 内部的 `b0_raw_reg..b8_raw_reg`**！） |
| `Inter_C_window_0_0 .. 2_2` | **3 × 3** | 9 个色度整数像素，同时喂给 4 个并行 `CPE` 算 2×2 共 4 个色度像素 |
| `Inter_bi_window_0 .. 3` | **4** | 4 个整数像素，供 `pos_a/c/d/n` 做 1/4 像素双线性平均 |
| `Inter_pix_copy0 .. 3` | **4** | 整数位置直接复制（亮度 `pos_Int` 按列复制 4 像素；色度 `Is_InterChromaCopy` 复制 2×2 块） |

对于偏右/偏下的 1/4 位置，滑窗只需把索引顺移 `+1`：
- `pos_p / pos_r`：`Inter_H_window` 下移 `+1` 行（算下一行半像素 `s`）；
- `pos_g / pos_r / pos_k`：`Inter_V_window` 右移 `+1` 列（算右一列半像素 `m`）；
- `pos_c`（右移 `+1` 列）与 `pos_n`（下移 `+1` 行）体现在 `Inter_bi_window`。

## 6.4 亮度插值引擎：`Inter_pred_LPE.v`（590 行）

### 1. 16 种分数像素位置编码（`nova_defines.v:257-272`）

`pos_FracL = {xFracL[1:0], yFracL[1:0]}`（高 2 位是 x 小数，低 2 位是 y 小数）：

```text
  yFrac \ xFrac   00(0)       01(1/4)     10(1/2)     11(3/4)
    00 (0)        pos_Int     pos_a       pos_b       pos_c
    01 (1/4)      pos_d       pos_e       pos_f       pos_g
    10 (1/2)      pos_h       pos_i       pos_j       pos_k
    11 (3/4)      pos_n       pos_p       pos_q       pos_r
```

### 2. 零乘法 6-tap 滤波器（`Inter_pred_LPE.v:520-579`）

目标计算 `raw_out = A − 5B + 20C + 20D − 5E + F = (A+F) − 5(B+E) + 20(C+D)`。
令 `P = A+F`, `Q = B+E`, `R = C+D`，看 `filterH_6tap`（`:520-548`）如何用 **3 级纯加法 + 移位** 完成：

```verilog
assign sum_AF  = A + F;                                    // P
assign sum_BE  = B + E;                                    // Q
assign sum_CD  = C + D;                                    // R
assign sum_4CD = {sum_CD, 2'b0};                           // 4R
assign sum_1   = {1'b0, sum_4CD} + {3'b111, ~sum_BE} + 1;  // 4R - Q
assign sum_2   = {4'b0, sum_AF}  + {sum_1[11], sum_1};     // P + 4R - Q
assign sum_3   = {sum_1, 2'b0};                            // (4R - Q) * 4 = 16R - 4Q
assign raw_out = {{2{sum_2[12]}}, sum_2} + {sum_3[13], sum_3}; // P - 5Q + 20R !
```

**手算验证一下**：`sum_2 + sum_3 = (P + 4R − Q) + (16R − 4Q) = P − 5Q + 20R` —— 精确恒等，**0 个乘法器**！
- **水平舍入**（`filterH_6tap:545-547`）：当 `H_need_round == 1` 时算 `(raw_out + 16) >> 5` 并裁剪到 `[0, 255]`。
  在 9 个水平滤波器中，**4 个（`H0, H1, H7, H8`）硬连线 `H_need_round = 1'b0`**（它们只在二维 6-tap 时提供外围行 `raw_out`），**5 个（`H2..H6`）接 `H_need_round`**；注意 **`pos_f` 和 `pos_q` 时 `H_need_round == 1`**（它们既需要 `raw_out` 喂垂直 6-tap 算 `j`，又需要 `round_out` 锁存水平半像素 `b`！），而 `pos_i / j / k` 时 `H_need_round == 0`。
- **垂直 6-tap**（`filterV_6tap:550-579`）：完全相同的三级加法树，输入位宽扩到 15-bit 有符号：
  - `Is_V_jfqik == 0`（输入为 8-bit 整数 `Inter_V_window`，算 `h`）：`(raw_out + 16) >> 5`；
  - `Is_V_jfqik == 1`（输入为 15-bit 水平中间值 `b0_raw_reg..b8_raw_reg`，算 `j`）：`(raw_out + 512) >> 10`（合并两次 `>> 5` 并一次性四舍五入，严格符合 H.264 精度要求）。
- **双线性平均**（`bilinear:581-588`）：`(A + B + 1) >> 1`。

### 3. 为什么 `pos_j/f/q` 要 5 拍，而 `pos_i/k` 要 8 拍？（核心逐拍拆解！）

亮度引擎和帧内预测一样，也是**每拍算 1 列（4 个垂直像素）**。一个 4×4 块共 4 列，但不同分数位置的硬件数据依赖不同（`Inter_pred_pipeline.v:379-383`）：

1. **普通位置（11 种：`Int, a, b, c, d, h, n, e, g, p, r`）→ 4 拍（`cnt = 4, 3, 2, 1`）**
   每拍 1 列纯组合完成！例如 `pos_e/g/p/r`：同一拍内 `H2..5` 算水平半像素 `b`、`V0..3`（`Is_V_jfqik=0`）算垂直半像素 `h`、`bilinear0..3` 把两者平均直接输出，4 列刚好 4 拍。
2. **`pos_j / pos_f / pos_q` → 5 拍（`cnt = 5, 4, 3, 2, 1`，2 级列流水！）**
   因为算 `j` 必须先算水平 `b_raw` 再寄存（打 1 拍）喂给垂直 `V0..3`，所以用了 **1 拍填流水 + 4 拍重叠输出**：
   - `cnt = 5`：`H0..8` 算第 0 列的 9 个 `b_raw` → 存入 `b0_raw_reg..b8_raw_reg`（若是 `f/q`，同时把 `H2..5`/`H3..6` 的 `round_out` 存进 `b0_reg..b3_reg`）；本拍无有效输出；
   - `cnt = 4, 3, 2`：`H0..8` 提前算下一列 `c+1`，同时 `V0..3`（`Is_V_jfqik=1`）对第 `c` 列的 `b_raw_reg` 做垂直 6-tap 得 `j`（`pos_j` 直接输出；`pos_f/q` 再经 `bilinear(b_reg, j)` 输出）；
   - `cnt = 1`：`V0..3`（+ `bilinear`）输出最后第 3 列。
3. **`pos_i / pos_k` → 8 拍（`cnt = 8, 7, 6, 5, 4, 3, 2, 1`，结构冒险！）**
   H.264 规定 `i = avg(h, j)`、`k = avg(h_right, j)`。**算 `h` 和算 `j` 都需要用到同一套 4 个 `filterV_6tap`！** 硬件上只有 1 套垂直滤波器，冲突无法同拍并行，只好每列拆成 **2 拍**（4 列 × 2 拍 = 8 拍）：
   - **偶数拍（`cnt = 8, 6, 4, 2`，`Is_V_jfqik = 0`）**：`H0..8` 算本列 `b_raw` → `b_raw_reg`；同时 `V0..3` 滤整数像素列 `Inter_V_window` 算出 `h`（或 `h_right`）→ 存入 `h0_reg..h3_reg`；
   - **奇数拍（`cnt = 7, 5, 3, 1`，`Is_V_jfqik = 1`）**：`V0..3` 改滤 `b_raw_reg` 算出 `j`，随即送入 `bilinear(h_reg, j)` 输出最终的 `i` 或 `k`！

### 4. 全部 16 种亮度位置的精确输出源（`Inter_pred_LPE.v:463-516` + `Inter_pred_pipeline.v:710-742`）

| 位置 | 输出路径 | 实际运算 | 耗时 |
|---|---|---|---|
| `pos_Int` | `Inter_pred_pipeline` 直通 `Inter_pix_copy` | 直接复制整数像素 | 4 拍 |
| `pos_b` | `LPE` → `H_6tapfilter2..5_round_out` | 水平 6-tap（`+16>>5`） | 4 拍 |
| `pos_h` | `LPE` → `V_6tapfilter0..3_round_out` (`Is_V=0`) | 垂直 6-tap（`+16>>5`） | 4 拍 |
| **`pos_j`** | `LPE` → `V_6tapfilter0..3_round_out` (`Is_V=1`) | 先 H 未舍入 → 再 V（`+512>>10`） | **5 拍** |
| `pos_a, pos_c` | `LPE` → `bilinear(Inter_bi_window, H_round)` | 整数与 `b` 平均 | 4 拍 |
| `pos_d, pos_n` | `LPE` → `bilinear(Inter_bi_window, V_round)` | 整数与 `h` 平均 | 4 拍 |
| `pos_e, g, p, r` | `LPE` → `bilinear(H_round, V_round)` | `b/s` 与 `h/m` 平均 | 4 拍 |
| `pos_f, pos_q` | `LPE` → `bilinear(b_reg, V_round[j])` | 寄存的 `b/s` 与 `j` 平均 | **5 拍** |
| `pos_i, pos_k` | `LPE` → `bilinear(h_reg, V_round[j])` | 寄存的 `h/m` 与 `j` 平均 | **8 拍** |

## 6.5 色度双线性插值：`Inter_pred_CPE.v`（149 行）

色度（4:2:0 尺寸减半）MV 精度自动变为 **1/8 像素**（`xFracC, yFracC ∈ 0..7`），公式为双线性加权：

```text
pred = ( (8−xFracC)(8−yFracC)·a + xFracC(8−yFracC)·b
       + (8−xFracC)yFracC·c     + xFracC·yFracC·d + 32 ) >> 6
```

`Inter_pred_CPE.v` 的层次非常规整：
- 顶层 `Inter_pred_CPE`（`:18-77`）例化 **4 个 `CPE`**（`CPE0..3`），从 3×3 的 `Inter_C_window` 里**每拍并行算 2×2 共 4 个色度像素**；
- 每个 `CPE`（`:79-114`）内部例化 **4 个 `CPE_base`**（`CPE_base0..3`），分别算四个角 `a, b, c, d` 的加权项，再求和 `+ 32` 取 `[13:6]`（`>> 6`）；**全模块共 4 × 4 = 16 个 `CPE_base`**！
- 每个 `CPE_base`（`:116-144`）用**二进制位展开（条件左移 + 加法）**替代乘法器：
  ```verilog
  // 用 x[3:0] 的 4 位分别控制 ×8/×4/×2/×1 是否累加 → 得 x * Int_pel，再同理乘 y[3:0]
  assign sum_x3 = x[3] ? {Int_pel, 3'b0} : 0;  // ×8
  assign sum_x2 = x[2] ? {Int_pel, 2'b0} : 0;  // ×4
  assign sum_x1 = x[1] ? {Int_pel, 1'b0} : 0;  // ×2
  assign sum_x0 = x[0] ?  Int_pel        : 0;  // ×1
  assign sum_x  = (sum_x3 + sum_x2) + (sum_x1 + sum_x0);
  ```
  当分数位某 bit 为 0 时该支路直接输出 0（操作数隔离省动态功耗）。

> ⚠️ **核实源码里的过期注释（`Inter_pred_pipeline.v:313-314`）**：
> 源码注释写着 `Is_InterChromaCopy`（`xFracC==0 && yFracC==0`）能把计算周期“从 16 拍降到 4 拍”。但在实际 RTL（`:385-389`）中，因为已经用了 4 个并行 `CPE`，**无论是不是整数位置，4×4 色度的计算周期永远是 4 拍、2×2 色度永远是 1 拍**！`Is_InterChromaCopy` 真正省下的是 **Preload 预加载周期**（4×4 从 11 拍降到 5/9 拍；2×2 从 4/7 拍降到 3/5 拍）以及旁路 `CPE` 的动态功耗。

## 6.6 参考帧寻址、边界裁剪与预加载周期全表

### 1. 无乘法地址生成与越界复制（`Inter_pred_pipeline.v:547-700`, `Inter_pred_reg_ctrl.v:117-140`）

- 坐标裁剪：`xInt_addr` 负值裁到 `0`，亮度最大裁到 **`172`**（`176−4`，因为每次读 4 像素 word 覆含 172..175），色度最大裁到 **`84`**（`88−4`）；`yInt_addr` 裁到 `[0, 143]` / `[0, 71]`；
- 行跨距无乘法：`11y = 8y + 2y + y`，亮度再左移 2 位得 `44y`，色度左移 1 位得 `22y`；加上平面基址 `offset_constant`（Y=`0`, Cb=`6336`, Cr=`7920`）和字内列偏移 `xInt_addr[7:2]` 即得 14-bit `ref_frame_RAM_rd_addr`；
- **越界边缘像素复制（Replicate Padding）**：当 `xInt_addr_unclip_reg[8] == 1`（超出左边界），把读回 word 最左像素 `[7:0]` 复制 4 份；超出右边界（亮度 `> 43` 或色度 `> 21`），把最右像素 `[31:24]` 复制 4 份。注意 `xInt_addr_unclip_reg` 专门打了一拍，用来对齐外部帧存改成**同步读（1 拍延迟）**后的数据返回时刻！

| | `pos_d, h, n`（纯垂直） | **27** (`13×2+1`) | **40** (`13×3+1`) | 8×13 |
| | `pos_a, b, c`（纯水平） | **33** (`8×4+1`) | **33** | 13×8 |
| | `pos_e, g, p, r`（十字对角） | **49** (`4×3+9×4+1`) | **49** | 十字形 |
| | `pos_f, q, i, k, j`（全二维） | **53** (`13×4+1`) | **53** | **13×13** |
| **亮度 < 8×8**（每 4×4 均加载） | `pos_Int` | **5** | **9** | 4×4 |
| | `pos_d, h, n` | **10** | **19** | 4×9 |
| | `pos_a, b, c` | **13** | **13** | 9×4 |
| | `pos_e, g, p, r` | **24** | **24** | 十字形 |
| | `pos_f, q, i, k, j` | **28** (`9×3+1`) | **28** | **9×9** |
| **色度 ≥ 8×8**（4×4 色度） | 整数 (`0,0`) / 分数 | **5** / **11** | **9** / **11** | 4×4 / 5×5 |
| **色度 < 8×8**（2×2 色度子块） | 整数 (`0,0`) / 分数 | **3**(`!=3`) / **4**(`bit1=0`) | **5**(`==3`) / **7**(`bit1=1`) | 2×2 / 3×3 |

## 6.7 本章小结：帧间预测的四大工程权衡

1. **13×13 寄存器阵换 75% 外部带宽**：8×8 及以上划分一次预加载整个 `8+5=13` 窗口，4 个 4×4 块共享，省 3/4 帧存访存；空闲时由 `gclk_Inter_ref_rf` 彻底关断 1,352 个触发器的时钟。
2. **全加法器 6-tap + 条件移位 CPE**：亮度 6-tap（`P−5Q+20R`）与色度双线性全部 **0 乘法器**。
3. **2 级列流水 + 共享垂直 6-tap**：`pos_j/f/q` 仅需 5 拍；`pos_i/k` 为省一套 4×`filterV_6tap` 选择时分复用（8 拍），以极少出现频率换取显著面积节省。
4. **三层 MV 粒度与快速旁路**：`mv_is16x16`、`mv_below8x8`、`Is_InterChromaCopy` 让最常见的简单宏块走最短路径。
