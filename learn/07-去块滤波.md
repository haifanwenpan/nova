# 第 7 章 去块滤波（Deblocking Filter）

去块滤波是 `nova` 的**旗舰模块** —— 作者的 IEEE TCSVT 2008 论文（*A Five-Stage Pipeline, 204 Cycles/MB, Single-Port SRAM-Based Deblocking Filter for H.264/AVC*）就是专门写它的。由 4 个文件（2,137 行）构成：

| 文件 | 行数 | 职责 |
|---|---|---|
| `DF_top.v` | 204 | 顶层装配 + 例化 `DF_mbAddrA_RAM`（32×32）与 `DF_mbAddrB_RAM`（352×32） |
| `DF_pipeline.v` | 860 | 5 级流水核心算术（MR 查 `bs` → TD 阈值判决 → PRE 算 `delta`/裁剪 → FIR 强弱滤波与加 `delta`） |
| `DF_reg_ctrl.v` | 334 | MW 级片上缓存：`buf0..3`（4 组 4×4 缓冲）与 `t0, t1, t2`（3 组 4×4 字节转置缓冲） |
| `DF_mem_ctrl.v` | 739 | MW 级访存与地址控制：单端口 SRAM 读写调度、`DF_12_cycles` 收尾与外部帧存写回 |

> 📖 **概念预热**：块效应来源、边界强度 `bs=0..4` 含义、`p3..p0 | q0..q3` 像素命名 —— 见 [第 0 章 0.8 节](00-H.264基础.md)。

## 7.1 一个宏块要滤哪 48 条边？以及为什么是 204 cycles/MB？

每个宏块只滤自己的**左边界 + 内部垂直边**，以及**上边界 + 内部水平边**（右边界和下边界交给右边和下边的宏块去滤，避免重复）：
- **亮度（16×16 = 4×4 个 4×4 块）**：4 条垂直线 × 4 段（16 条）+ 4 条水平线 × 4 段（16 条）= **32 条边**；
- **色度 Cb / Cr（各 8×8 = 2×2 个 4×4 块）**：每平面 2 条垂直线 × 2 段 + 2 条水平线 × 2 段 = 8 条，两平面共 **16 条边**；
- 每条边长 4 像素，每拍滤 1 组 `p3..p0 | q0..q3`：
  - `48 条边 × 4 拍 = 192 拍`
  - 末尾将最后 3 个 Cr 4×4 块从转置缓冲写回外部帧存：`DF_12_cycles = 12 拍`
  - **稳态吞吐 = `192 + 12 = 204 拍/MB`**！
  - 加上 5 级流水线填充（4 拍）与末拍清零 `DF_duration`（1 拍），**单 MB 实测端到端宽度精确为 `209 拍`**（`gclk_DF` 因提前 1 拍在 `end_of_BS_DEC` 打开，共 **210 拍**）。

### 精确复习：边界强度 `bs`（0 ~ 4，H.264 8.7.2.1）

| `bs` | 触发条件（由 `bs_decoding.v` 预先算好） | 滤波器行为 |
|---|---|---|
| **4** | 任一侧为 Intra **且** 位于 16×16 **宏块边界**（V0 / H0） | 亮度走**强滤波**（条件不满足退化为 `bs4_weak_FIR`）；色度走 `bs4_weak_FIR`（仅改 `p0/q0`） |
| **3** | 任一侧为 Intra **且** 位于宏块**内部 4×4 边** | 正常滤波（`bs=1..3` 同一套公式，查 `bs=3` 裁剪表 `c1`） |
| **2** | 双侧 Inter，且任一侧有**非零变换残差** | 正常滤波（查 `bs=2` 裁剪表 `c1`） |
| **1** | 双侧 Inter、无残差，且参考帧不同或 `\|Δmvx\| ≥ 4 \|\| \|Δmvy\| ≥ 4` | 正常滤波（查 `bs=1` 裁剪表 `c1`） |
| **0** | 画面边界，或双侧 Inter 无残差同参考且 MV 差 < 1 像素 | **不滤波**（直通原像素，且各级操作数隔离清零省电） |

## 7.2 五级流水线分工（逐级核实源码）

```text
  Stage 1: MR       Stage 2: TD        Stage 3: PRE       Stage 4: FIR           Stage 5: MW
 (DF_pipeline:65)  (DF_pipeline:205)  (DF_pipeline:455)  (DF_pipeline:636)      (DF_reg_ctrl + DF_mem_ctrl)
 ┌──────────────┐  ┌───────────────┐  ┌───────────────┐  ┌───────────────────┐  ┌──────────────────────────┐
 │ 边计数 0..47 │─▶│ 查 alpha/beta │─▶│ 判 |p2-p0|<β  │─▶│ bs=4: 强/弱 FIR   │─▶│ 写入/转置到 buf0..3/t0..2│
 │ 读 SRAM/buf  │  │ 算 |p0-q0|<α  │  │ 查 c1/c0      │  │ bs=1..3: p0±δ0 裁剪│  │ 写回 DF_mbAddrA/B_RAM    │
 │ 查 bs_curr   │  │ 算 |p0-p1|<β  │  │ 算 δ0, δp1,δq1│  │   & p1+δp1, q1+δq1│  │ 写回外部 dis_frame_RAM   │
 │              │  │ 算 |q0-q1|<β  │  │ clip_to_c 裁剪│  │ 锁存到 p0..q3_MW  │  │ DF_12_cycles 收尾        │
 └──────────────┘  └───────────────┘  └───────────────┘  └───────────────────┘  └──────────────────────────┘
```

每一级都携带自己的计数器副本沿流水线打拍传递（`DF_edge_counter_MR → TD → PRE → FIR → MW`、`one_edge_counter_MR → ... → MW`），因此**任意时刻有 5 组相邻边/像素同时在 5 级中流动**。

## 7.3 第 1 级 MR：TCSVT 2008 混合滤波顺序（0..47）

H.264 标准默认是“先滤完 16 条垂直边、再滤完 16 条水平边”，但这需要把整个 16×16 宏块反复转置和缓存。`nova` 采用了 TCSVT 2008 论文提出的 **2 行条带混合交错顺序**（`DF_pipeline.v:101-178`），**只用 4 组 4×4 缓冲（`buf0..3`）就同时搞定垂直与水平滤波**！

看亮度 32 条边（`0..31`）分成完全对称的两半：
- **上半 2 行条带（块 0..7，边 `0..15`）**：
  - 边 `0, 1`（第 0 行 V0, V1）→ 边 `2, 3`（第 1 行 V0, V1）→ 边 `4, 5`（第 0 列 H0, H1，此时左上 2 块已完成左右垂直滤波，立刻滤完横边就能吐出写进帧存腾出 `buf`！）
  - 边 `6, 7`（第 0/1 行 V2）→ 边 `8, 9`（第 1 列 H0, H1）
  - 边 `10, 11`（第 0/1 行 V3）→ 边 `12, 13`（第 2/3 列 H0）→ 边 `14, 15`（第 2/3 列 H1）
- **下半 2 行条带（块 8..15，边 `16..31`）**：与 `0..15` 完全同构！其中特别注意 **边 `18` 是垂直边 `bs_V0[11:9]`**（左邻 MB 的右下角块 15 与当前 MB 左下角块 12 之间的竖边）！
- **色度 Cb（`32..39`）与 Cr（`40..47`）**：同样“先竖后横”交替：`32..35` / `40..43` 是 4 条垂直边（其中 **边 `34`、`42` 是左边界最底下的垂直边 `bs_V0[8:6]/[11:9]`**！），`36..39` / `44..47` 是 4 条水平边。

**精简标志位（`DF_pipeline.v:93-94`）**：`DF_edge_counter_MR` 复位到空闲态 `48`，靠最高位 `[5]` 一个 bit 直接区分亮度与色度：
- `0..31`（`[5]==0`）：`lumaEdgeFlag_MR = 1`
- `32..47`（`[5]==1 && !=48`）：`chromaEdgeFlag_MR = 1`

## 7.4 第 2 级 TD：阈值判决与 80% 省 ROM 的 `beta` 算法

### 1. 每 MB 只算一次 `indexA / indexB`（`DF_pipeline.v:209-234`）

`indexA = Clip(0, 51, QP + 2 × slice_alpha_c0_offset_div2)`，`indexB` 同理。由于同一 MB 内 QP 不变，`indexA/B_y/c_reg` 直接挂在 **`gclk_end_of_MB_DEC`** 上，每 MB 仅锁存 1 次（而不是每边查 48 次）。

### 2. 用移位减法消灭 26 项 `beta` 查表（`DF_pipeline.v:255-266`）

对比 H.264 Table 8-16 的 `beta` 表，你会发现从 `indexB = 26` 开始，它呈现完美的阶梯线性规律：

```text
indexB: 26  27  28  29  30  31  32  33 ... 50  51
beta  :  6   6   7   7   8   8   9   9 ... 18  18   ← 恰好等于 floor(indexB / 2) - 7 !
```

因此 `DF_pipeline.v:255-266` 只用 3 个分支写 `16..25`，后面 26 项合并成一行：

```verilog
if      (indexB < 16) beta <= 0;
else if (indexB < 26)
    case (indexB)
        6'd16, 6'd17, 6'd18        : beta <= 8'd2;
        6'd19, 6'd20, 6'd21, 6'd22 : beta <= 8'd3;
        6'd23, 6'd24, 6'd25        : beta <= 8'd4;
        default                    : beta <= 0;
    endcase
else
    beta <= indexB[5:1] - 3'd7;  // (indexB >> 1) - 7，省掉 26 项 ROM！
```

### 3. 三路绝对值比较与操作数隔离（`DF_pipeline.v:401-453`）

- 当 `bs_curr_TD == 0` 或 `disable_DF == 1` 时，三个 `absolute` 比较器的输入强制清零（**第 1 层操作数隔离**）；
- 只有当 `(|p0 − q0| < alpha) && (|p0 − p1| < beta) && (|q0 − q1| < beta)` 同时成立时，`threshold == 1`；
- 传递到 PRE 级时，若 `threshold == 0` 则把 `bs_curr_PRE` 清零，屏蔽后续两级所有运算，而原始像素 `p0..p3, q0..q3` 照常向下直通写回！

## 7.5 第 3 级 PRE：二次平滑判据、增量 `delta` 与对称裁剪

PRE 级完成三件事（`DF_pipeline.v:455-634`）：
1. **计算 3 个二次判据**（仅亮度和 `bs != 0` 时启用，色度直接短路为 0）：
   - `p2_m_p0_less_beta` = `(|p2 − p0| < beta)`（决定 p 侧是否足够平滑，允许改 `p1` 或强滤 `p0..p2`）
   - `q2_m_q0_less_beta` = `(|q2 − q0| < beta)`（决定 q 侧是否允许改 `q1` 或强滤 `q0..q2`）
   - `p0_m_q0_less_alpha_shift` = `(|p0 − q0| < (alpha >> 2) + 2)`（仅 `bs == 4` 亮度启用，强滤波收紧门限）
2. **查裁剪限幅 `c1`（`tC0`）并推 `c0`（`tC`）**（`:486-547`）：
   - 按 `bs ∈ {1, 2, 3}` 和 `indexA_PRE` 查表得 `c1 ∈ [0, 25]`；
   - 亮度 `c0 = c1 + p2_m_p0_less_beta + q2_m_q0_less_beta`；色度 `c0 = c1 + 1`；
3. **无乘法算 `delta` 并做对称裁剪 `clip_to_c`**（`:550-592, 796-810`）：
   - `delta_0i = ((q0 − p0) × 4 + (p1 − q1) + 4) >> 3`（H.264 8-334；代码中 `+ 5` 是补码取反 `~q1` 补偿 `+1` 再加舍入 `+4`）；
   - `delta_p1i = (p2 + ((p0 + q0 + 1) >> 1) − (p1 << 1)) >> 1`（H.264 8-341；`-(p1<<1)` 写成 `{1'b1, ~p1, 1'b1} + 1`）；`delta_q1i` 镜像；
   - 3 个 `clip_to_c` 子模块分别把 `delta_0i` 裁到 `[-c0, +c0]`、把 `delta_p1i/q1i` 裁到 `[-c1, +c1]`，输出 6-bit 有符号 `delta_0 / delta_p1 / delta_q1`（其中 `delta_p1/q1` 在不满足 `less_beta` 时再清零一次，形成**第 2 层操作数隔离**）。

## 7.6 第 4 级 FIR：强/弱滤波、加 `delta` 与锁存至 `*_MW`

FIR 级（`DF_pipeline.v:636-786`）同时承接 **`bs == 4`** 和 **`bs ∈ {1, 2, 3}`** 两条分支，并在本级末的时钟沿统一锁存出最终滤波像素 `p0_MW..q3_MW`：

### 分支 A：`bs == 4`（`DF_pipeline.v:638-755, 812-860`）

- **`bs4_strong_FIR`（`:812-845`）**：利用公共子项 `sum_0 = (p0+q0)+(p1+p2)`、`sum_1 = (p0+q0)+(p1+q1)`、`sum_2 = (p0+q0)+(q1+q2)`，**0 乘法器**同时算出 H.264 (8-344~8-349) 的 6 个强滤波输出：
  ```text
  p0' = (p2 + 2p1 + 2p0 + 2q0 + q1 + 4) >> 3    = (sum_0 + sum_1 + 4) >> 3
  p1' = (p2 +  p1 +  p0 +  q0      + 2) >> 2    = (sum_0 + 2) >> 2
  p2' = (2p3 + 3p2 + p1 +  p0 + q0 + 4) >> 3    = (2(p2+p3) + sum_0 + 4) >> 3
  （q0', q1', q2' 完全镜像）
  ```
  不满足强滤波条件时，8 个输入像素全部门控清零（**第 3 层操作数隔离**）。
- **`bs4_weak_FIR0 / 1`（`:847-860`）**：算 `(2a + b + c + 2) >> 2`，即 `p0' = (2p1 + p0 + q1 + 2) >> 2` 与 `q0' = (2q1 + q0 + p1 + 2) >> 2`。
- **精确输出选择（`DF_pipeline.v:736-755`）**：
  - **亮度 `bs == 4`**：只有当 **`p0_m_q0_less_alpha_shift_FIR && p2_m_p0_less_beta_FIR`** 同时满足时，`p0_MW, p1_MW, p2_MW` 才全部选强滤波输出，否则 `p0_MW` 退化为 `bs4_weak_FIR0_out`、`p1_MW / p2_MW` 保持原值 `p1_FIR / p2_FIR`！（`q` 侧同理检查 `p0_m_q0_less_alpha_shift_FIR && q2_m_q0_less_beta_FIR`）。
  - **色度 `bs == 4`**：`p0_MW <= bs4_weak_FIR0_out`，`q0_MW <= bs4_weak_FIR1_out`，`p1_MW, p2_MW, q1_MW, q2_MW` 全部直接锁存原值 `p1_FIR..q2_FIR`。

### 分支 B：`bs ∈ {1, 2, 3}`（`DF_pipeline.v:715-769`）

同样在 **第 4 级 FIR** 组合算出修正结果并锁存进 `*_MW`：
- `p0_MW_tmp = {2'b0, p0_FIR} + {{4{delta_0[5]}}, delta_0}`（10-bit）；`q0_MW_tmp = q0_FIR − delta_0`（用 `~delta_0 + 1` 取负）；各自用 `tmp[9]`（负→0）和 `tmp[8]`（≥256→255）无比较器饱和裁剪；
- 亮度 `p1_MW`（仅 `p2_m_p0_less_beta_FIR == 1` 时修改）：`p1_FIR + {delta_p1[5], delta_p1[5], delta_p1}`（将 6-bit 有符号 `delta_p1` 符号扩展到 8-bit 相加，规范保证不溢出）；`q1_MW` 镜像；`p2_MW / q2_MW` 与 `p3_MW / q3_MW` 保持原值直通。

## 7.7 第 5 级 MW：转置缓冲、单端口 SRAM 与边缘 `18/34/42` 的精妙回写

第 5 级 MW 由 `DF_reg_ctrl.v` 和 `DF_mem_ctrl.v` 共同完成，解决了去块滤波最棘手的三个工程难题：

### 难题 1：竖边变横边必须 4×4 转置（`DF_reg_ctrl.v`）

垂直滤波 4 拍吐出的是 4 行的水平像素，而紧接着的水平滤波和外部帧存写回都需要按列/按行对齐。`DF_reg_ctrl.v` 用 **4 拍逐字节写入 4 个 32-bit 寄存器** 实现**零额外逻辑的 4×4 转置**：

```verilog
// DF_reg_ctrl.v（转置写入示例：4 拍后 buf0_0 存满 4 个 p3，buf0_3 存满 4 个 p0！）
case (one_edge_counter_MW)
    2'd0: begin buf0_0[7:0]   <= p3_MW; buf0_1[7:0]   <= p2_MW; buf0_2[7:0]   <= p1_MW; buf0_3[7:0]   <= p0_MW; end
    2'd1: begin buf0_0[15:8]  <= p3_MW; buf0_1[15:8]  <= p2_MW; buf0_2[15:8]  <= p1_MW; buf0_3[15:8]  <= p0_MW; end
    2'd2: begin buf0_0[23:16] <= p3_MW; buf0_1[23:16] <= p2_MW; buf0_2[23:16] <= p1_MW; buf0_3[23:16] <= p0_MW; end
    2'd3: begin buf0_0[31:24] <= p3_MW; buf0_1[31:24] <= p2_MW; buf0_2[31:24] <= p1_MW; buf0_3[31:24] <= p0_MW; end
endcase
```

除了 `buf0..3`（在竖边/横边之间周转 4×4 块），还有 3 组专用转置缓冲：
- **`t0`**：在水平边（`4,8,12,15,20,24,28,31,36,39,44,47`）转置暂存 `p` 侧像素，用于写回外部帧存（`mbAddrB`、`currMB`、收尾 `blk21`）及 `DF_mbAddrA_RAM`；
- **`t1`**：转置暂存 `p` 或 `q`（`31,39,47` 时取 `q`），用于写回外部帧存（含收尾 `blk23`）及 `DF_mbAddrA_RAM`；
- **`t2`（最精妙的一处！）**：**专门解决“跨宏块二次修改”问题**！

### 难题 2：边 `18 / 34 / 42` 与 `t2` 的真实来历（核实纠正！）

看懂边 `18 / 34 / 42`，你就真正吃透了单端口去块滤波的数据流：
- 当**左边那个宏块（`mb_num_h - 1`）**滤波结束时，它最底下一行的 4 个 4×4 块（含右下角那个块）已经存进 **`DF_mbAddrB_RAM`**，留给下一行宏块做上边界滤波；
- 现在轮到**当前宏块（`mb_num_h`）**滤波。走到 **边 `18`（亮度左边界最底段 `bs_V0[11:9]`）、边 `34`（Cb 左边界底段）、边 `42`（Cr 左边界底段）** 这 **3 条垂直边**时，滤波器的 `p` 侧恰好是**左邻宏块的右下角 4×4 块**！
- 垂直滤波可能会改动这几个像素！如果只写回外部帧存而不更新 `DF_mbAddrB_RAM`，那么等解码到下一行宏块时，它从 `DF_mbAddrB_RAM` 读到的左邻底边像素就是**过时的旧值**！
- 因此 `DF_reg_ctrl.v:313-333` 在边 `18 / 34 / 42` 把 `p` 侧转置存入 **`t2`**，`DF_mem_ctrl.v` 在边 `20 / 37 / 45` 把 `t2` **回写覆盖到 `DF_mbAddrB_RAM` 里左邻宏块（`mb_num_h_DF - 1`）对应的槽位**！
- 这也解释了为什么 `DF_mem_ctrl.v:123-129` 强制规定：**边 `18 / 34 / 42` 即使 `bs == 0` 也必须读出 `DF_mbAddrA_RAM`**，否则 `t2` 会把错误数据写坏左邻的 `mbAddrB`！

### 难题 3：单端口 SRAM 零冲突与 `DF_12_cycles` 收尾

`DF_top.v:183-204` 例化了两块同步单端口 SRAM（`ram_sync_1r_sync_1w`，注意该模型端口是 `.wr_addr` / `.rd_addr` / `.wr_n` / `.rd_n`）：
- **`DF_mbAddrA_RAM`（32 × 32-bit = 128 B）**：存左邻 MB 最右边的 **8 个 4×4 块**（4 亮度 + 2 Cb + 2 Cr，每块 4 word = 32 word）；
- **`DF_mbAddrB_RAM`（352 × 32-bit = 1,408 B）**：存整行 11 个 MB 各自的 8 个底边/中间行 4×4 块（`11 × 32 = 352 word`），在 `DF_top.v:200-201` 里 `.wr_addr` 和 `.rd_addr` 直接绑在同一根 9-bit 地址线 `DF_mbAddrB_RAM_addr` 上！

之所以能用**单端口 SRAM**，核心就一条：**读发生在第 1 级 MR，写发生在第 5 级 MW，经 `DF_mem_ctrl.v` 精确错拍调度，同一时钟周期永远不会同时既读又写！**

最后当边 `47` 的第 4 拍结束时，`DF_12_cycles`（**注意在 `DF_mem_ctrl.v:87-94` 是 `always @(posedge clk)` 同步复位，不是 `gclk_DF`！**）从 `0` 数到 `11`，用最后 **12 拍**把残留在片上缓冲的最后 3 个 Cr 4×4 块依次写进外部帧存和 `DF_mbAddrA_RAM`：
- `0..3`：`buf2` → `blk22`（外部帧存）
- `4..7`：`t0` → `blk21`（外部帧存 + `DF_mbAddrA_RAM` 槽 6）
- `8..11`：`t1` → `blk23`（外部帧存 + `DF_mbAddrA_RAM` 槽 7）

当 `DF_12_cycles == 11` 时（`DF_mem_ctrl.v:106-110`）：
- 若不是整帧最后一个宏块（`!(mb_num_h_DF == 10 && mb_num_v_DF == 8)`），拉高 **`end_of_MB_DF`**（每帧共 98 次）；
- 若是第 99 个宏块（`mb_num_h_DF == 10 && mb_num_v_DF == 8`），改拉高 **`end_of_lastMB_DF`**（每帧 1 次，用于清零 `DF_duration`，不触发下一宏块对齐）。

---

## 7.8 本章小结：去块滤波的五大设计精华

1. **6-bit 计数器统管 48 条边**：TCSVT 2008 2-row 混合滤波序，仅用 4 组 `buf` 消除整 MB 转置缓冲。
2. **每 MB 查 1 次 `indexA/B` + `beta = (indexB >> 1) - 7`**：砍掉 80% `beta` ROM。
3. **三级操作数隔离**：TD 级 `bs!=0`、PRE 级 `less_beta`、FIR 级强滤波使能逐级清零无效输入，极大降低 skip 宏块的动态功耗。
4. **单端口 SRAM + 5 级流水错开读写**：读在 MR、写在 MW，面积几乎砍半仍达到 **204 拍/MB** 稳态吞吐（实测精确 **209 拍/MB**）。
5. **关掉 DF 的量化验证**：跑 `./scripts/run_regression.sh -n 5 --nodb` 会看到 40% 像素变化、PSNR 从 `∞` 掉到 **46.35 dB**、单点 `maxdiff = 24`（见 [第 9.8 节](09-仿真环境与ffmpeg对比.md) 与 [第 11.4 节](11-动手实验.md)）。
