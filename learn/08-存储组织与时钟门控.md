# 第 8 章 存储组织与时钟门控

前 7 章讲的都是"算什么"。这一章讲**怎么省**——nova 的
**293 µW @ 1.0 V** 这个数字，一半靠算法（第 4–7 章的零乘法器），
另一半靠这一章的两个手段：

1. **片上存储的分级**：8 个寄存器堆（DFF）+ 5 个 SRAM，共 2.6 KB，
   全部**按"访问模式"选型**，不用一块大内存
2. **21 + 19 = 40 个门控时钟**：每个功能块**只在需要时才有钟**

## 8.1 两种存储器模型

nova 的 RTL 里只有**两个 RAM 行为模型**，所有存储都是它们的实例：

### 8.1.1 `ram_async_1r_sync_1w` —— 寄存器堆（RF）

```verilog
module ram_async_1r_sync_1w (clk, rst_n, cs_n, wr_n, rd_addr, wr_addr, data_in, data_out);
    parameter data_width = 32;      // 合法 1..128
    parameter data_depth = 32;      // 合法 2..256
```

**头注释（原文）**：

```
// Synch Write, Asynch Read RAM, NOT synthesizable
// In real silicon, use register file (DFF) instead of RAM
```

**两个关键点**：

1. **异步读 = 组合逻辑**：`assign data_out = ram[rd_addr];` —— **零周期延迟**
2. **综合成 DFF**：不是 SRAM，是 **触发器阵列**

```verilog
// 读端口（组合）
assign data_out = ((rd_addr ^ rd_addr) !== {addr_width{1'b0}})
                  ? {data_width{1'bx}}       // rd_addr 有 X → 输出 X
                  : ((rd_addr >= data_depth) ? {data_width{1'b0}} : ram[rd_addr]);

// 写端口（同步）
always @ (posedge clk)
    if (!cs_n && !wr_n)
        ram[wr_addr] <= data_in;
```

**注意那个 `(rd_addr ^ rd_addr) !== 0`**：这是**检测 `rd_addr` 里有没有 X**。
如果地址有 X，输出 X 而不是"随便读一个"——**这是为了仿真时能立刻发现 bug**，
综合时会优化掉。

### 8.1.2 `ram_sync_1r_sync_1w` —— 真正的 SRAM

```verilog
module ram_sync_1r_sync_1w (clk, rst_n, wr_n, rd_n, wr_addr, rd_addr, data_in, data_out);
    parameter data_width = 32;      // 合法 1..256
    parameter data_depth = 96;      // 合法 2..1024
```

**头注释（原文）**：

```
// Synch Write, Synch Read RAM, NOT synthesizable
// In real silicon, use customized RAM instead of DFF
```

**同步读 = 1 周期延迟**：

```verilog
always @ (posedge clk or negedge rst_n)
    if (rst_n == 1'b0)
        data_out <= 0;
    else if (!rd_n)
        data_out <= ram[rd_addr];
```

**这两个模型的差别决定了整个设计的时序结构**：

| | `ram_async_1r_sync_1w` | `ram_sync_1r_sync_1w` |
|---|---|---|
| 读延迟 | **0 cycle**（组合）| **1 cycle** |
| 综合成 | DFF（触发器）| 定制 SRAM |
| 位宽上限 | 128 | 256 |
| 深度上限 | 256 | 1024 |
| 面积/bit | 大（~6 个晶体管/bit）| 小（~1 个晶体管/bit）|
| 功耗/bit | 高 | 低 |

**nova 的选择原则**：

- **小而快**（20~32 项、11~32 bit）→ RF（异步读，零周期）
- **大而慢**（88~352 项、32 bit）→ SRAM（同步读，1 周期）

**`ram_sync_1r_sync_1w.v` 里有一段被注释掉的检查代码**：

```verilog
/* if (cs_n == 0 && wr_n == 0 && rd_n == 0) begin
       $display("Error: Simultaneous read and write");
       $finish;
   end */
```

**这段被注释掉**说明：设计上**靠时序错开保证读写不冲突**，而不是靠检查。
这直接引出第 7.9 节的"单端口 SRAM"设计（读写分处流水两端）。

```
= 21248 bit = 2656 byte ≈ 2.6 KB
```

### 8.2.3 为什么 `Intra_mbAddrB_RAM` 是 88 项

**88 = 8（luma 一行 8 个 4×4 块）× 4（每个块 4 像素宽）+ 8（chroma 两个平面各 2×2 块）**
… 实际拆解：

- **luma**：176 像素一行 = **44 word**（4 像素/word）→ 保留 2 行缓冲？不，是 **88 = 44 × 2**
- 但 spec 说 Intra 只需要**上邻 MB 的一行像素**（176 宽 = 44 word）+ **上邻的右下 4 像素**（右上参考）
- **88 = 44（本 MB 位置的 luma）+ 44（上邻右下的延伸）**？

**实际用途**：`Intra_mbAddrB_RAM` 存的是**上邻 MB 的最后一行 luma（44 word）+ 两个 chroma 平面各 22 word**：

```
44 (luma) + 22 (Cb) + 22 (Cr) = 88 word ✓
```

**这就对上了**！**它不是"额外的一行"，而是"上邻 MB 的完整底边"**
（luma 一行 + Cb 一行 + Cr 一行）。

### 8.2.4 `rec_DF_RAM0/1` 的双缓冲

**96 = luma 32 + Cb 32 + Cr 32**？不对。

**96 word = 24 个 4×4 块 × 4 word**：

```
16 (luma 4×4 块) + 4 (Cb) + 4 (Cr) = 24 块
24 块 × 4 word/块 = 96 word ✓
```

**所以 `rec_DF_RAM0/1` 存的是"一个 MB 的全部重建结果"**（24 个 4×4 块）。
**双缓冲**的含义是：

- 一块正在被 `sum.v` 写（当前 MB）
- 另一块正在被 `DF` 读（上一个 MB）

**`rec_DF_RAM_ctrl.v` 负责切换**：

```verilog
// reconstruction.v:585-607
ram_sync_1r_sync_1w rec_DF_RAM0 (.clk(gclk_rec_DF_RAM0), ...);
ram_sync_1r_sync_1w rec_DF_RAM1 (.clk(gclk_rec_DF_RAM1), ...);
rec_DF_RAM_ctrl rec_DF_RAM_ctrl (.clk(clk), .reset_n(reset_n),
    .disable_DF(disable_DF), .end_of_MB_DEC(end_of_MB_DEC),
    .DF_edge_counter_MR(DF_edge_counter_MR), .one_edge_counter_MR(one_edge_counter_MR),
    .blk4x4_sum_PE0_out(blk4x4_sum_PE0_out), ..., 
    .rec_DF_RAM_dout(rec_DF_RAM_dout), ...);
```

**为什么需要双缓冲？** 因为 `sum.v` 和 `DF` 是**并行流水**的：

```
时间 →
MB n:   [ sum 写 rec_DF_RAM0 ][ DF 读 rec_DF_RAM0 ]
MB n+1:                        [ sum 写 rec_DF_RAM1 ][ DF 读 rec_DF_RAM1 ]
```

**MB n 的 DF 还没读完，MB n+1 的 sum 就要开始写** —— 所以必须两块。

## 8.3 时钟门控：40 个门控时钟

### 8.3.1 为什么需要门控时钟

**动态功耗公式**：

```
P_dynamic = α · C · V² · f
```

- `α`：翻转率（activity）
- `C`：电容
- `V`：电压
- `f`：频率

**门控时钟（clock gating）的作用**：把 `α` 里"时钟树翻转"这一部分干掉。
**时钟树通常占芯片动态功耗的 20–40%**（因为它扇出到所有触发器）。

**如果某个功能块这个周期不干活，就没必要给它时钟。**

### 8.3.2 标准 ICG 单元的行为模型

nova 用**负沿锁存器 + 与门**来模拟 ICG（Integrated Clock Gating）单元：

```verilog
wire  X_ena;
reg   l_X_ena;
assign X_ena = <使能条件>;
always @ (clk or X_ena)
    if (!clk)                 // ← 负沿锁存！
        l_X_ena <= X_ena;
assign gclk_X = clk & l_X_ena;
```

**为什么必须用负沿锁存？** 防止**毛刺**：

```
clk  ──┐  ┌──┐  ┌──
       └──┘  └──┘

X_ena ────────┐________________  （在 clk 高电平期间变化）
              ↑
         如果直接 & 会在这里产生一个窄脉冲！

l_X_ena ──────────────┐________  （负沿才采，高电平期间稳定）
                      ↑
                   与门输出干净
```

**ICG 单元在真实工艺库里就是这么实现的**（一个负沿锁存器 + 一个与门，
有些库用或门实现）。nova 用 RTL 写出这个行为，**综合工具能识别并映射到库里的 ICG cell**。

### 8.3.3 两种不同的门控方式

nova 里的门控时钟有**两种语义**，必须分清：

**方式 A：电平使能（持续多个周期）**

```verilog
assign DF_ena = DF_duration | end_of_BS_DEC;
always @ (clk or DF_ena) if (!clk) l_DF_ena <= DF_ena;
assign gclk_DF = clk & l_DF_ena;
```

**`DF_duration` 是一个持续 204 个周期的电平** → `gclk_DF` 在这 204 个周期里都有钟。

**方式 B：脉冲使能（单周期脉冲）**

```verilog
always @ (clk or end_of_MB_DEC) if (!clk) l_end_of_MB_DEC <= end_of_MB_DEC;
assign gclk_end_of_MB_DEC = l_end_of_MB_DEC & clk;
```

**`end_of_MB_DEC` 是一个单周期脉冲** → `gclk_end_of_MB_DEC` **每个 MB 只有一个时钟沿**。

**为什么需要方式 B？** 因为有些寄存器**只在特定事件时更新一次**（比如 MB 结束时的
`blk4x4_rec_counter` 归零）。用脉冲门控时钟，**这些寄存器在其余 200 多个周期里
完全不翻转**。

**这是本章最重要的设计思想**：

> **不是"用一个全局时钟 + 一堆 enable 信号"，
> 而是"给每个寄存器组一个只在需要时才有沿的时钟"。**

**代价**：门控时钟多了一层延后（负沿锁存），时序分析要按 gclk 分析。
**收益**：省掉 enable MUX 的面积 + 省掉时钟树翻转的功耗。

### 8.3.4 三个文件的分工

| 文件 | 行数 | 门控时钟数 | 管什么 |
|---|---|---|---|
| `bitstream_gclk_gen.v` | 332 | **19** | 位流解析链路（parser / nal / sps / pps / slice / residual / cavlc / bs_dec / 8 个 RF）|
| `rec_gclk_gen.v` | 426 | **21** | 重建链路（IQIT / intra / inter / sum / DF / 5 个 SRAM）|
| **合计** | **758** | **40** | — |

**两个文件结构几乎一样**，只是服务的模块不同。**分两个文件是因为两条链路的
状态信号完全独立**（解析链路看 `parser_state`，重建链路看 `blk4x4_rec_counter`）。

### 速率控制的三层嵌套

`bitstream_gclk_gen.v` 里还有一个**和门控无关但放在一起**的功能——**帧率控制**：

```verilog
// bitstream_gclk_gen.v:88-125
reg [16:0] cycles_per_frame;

always @ (...)
    case ({freq_ctrl1, freq_ctrl0})
        2'b00: cycles_per_frame <= `cycles_per_frame0;   // 45000
        2'b01: cycles_per_frame <= `cycles_per_frame1;   // 50000
        2'b11: cycles_per_frame <= `cycles_per_frame3;   // 70000
        default: cycles_per_frame <= `cycles_per_frame2; // 57300
    endcase

always @ (posedge clk or negedge reset_n)
    if (reset_n == 1'b0)
        begin frame_cycle_counter <= 0; end_of_one_frame <= 1'b0; end
    else if (parser_state == `start_code_prefix)
        begin frame_cycle_counter <= 0; end_of_one_frame <= 1'b0; end
    else if (frame_cycle_counter < cycles_per_frame)
        frame_cycle_counter <= frame_cycle_counter + 1;
    else
        begin frame_cycle_counter <= 0; end_of_one_frame <= 1'b1; end
```

**三层嵌套**：

1. **帧级**：`end_of_one_frame` 限制**解析器**多久才能开始解下一帧
2. **MB 级**：`mb_num == 98` 判断（QCIF 最后一个 MB）
3. **块级**：`blk4x4_rec_counter` 等

**为什么要限制解析器的启动时刻？**

因为 nova 的**重建流水线比解析慢**（每个 MB 需要 ~450 周期，而解析一个 MB
的位流只要几十周期）。如果解析器不受限，它会一路解析下去，**把残余系数
寄存器覆盖掉**。

**所以 `cycles_per_frame` 本质是"给重建流水线的追赶时间"**。

**`freq_ctrl` 四档的作用**：

| `{freq_ctrl1,freq_ctrl0}` | `cycles_per_frame` | 实测 cycles/frame（14 帧）| 逐帧增量 |
|---|---|---|---|
| `2'b00` | 45000 | **45009** | 精确 +45004 |
| `2'b01` | 50000 | **50009** | 精确 +50004 |
| `2'b10`（default）| 57300 | 57046 | 53352~57937（抖）|
| `2'b11` | 70000 | 68839 | 61265~70637（抖）|

**前两档的逐帧增量精确等于 `cycles_per_frame + 4`** —— 这 4 个周期是
帧边界握手开销（`end_of_one_frame` 拉高到解析器真正启动）。
说明这两档下**重建流水线有富余，完全在等速率控制的放行信号**。
后两档开始抖动，是因为瓶颈从"速率控制"转移到了"重建算力"，
而重建算力是内容相关的。

**关键事实：`freq_ctrl` 不改变 MB 级速度。** 用探针统计帧内 MB 间隔，
四档都是 **330 cycles/MB**，一个周期都不差。`freq_ctrl` 只控制
"解析器什么时候开始解下一帧"，与"跑一个 MB 要多久"完全正交。

**`cf0` 能不能调小？** 二分法实测：`42095` 会丢 40 个像素，`42100` 干净通过
（300 帧复验 PASS）。所以 **akiyo 的真实算力需求是 42100 cycles/帧**，
出厂值 45000 有 6.4% 余量。余量是留给 foreman 这类复杂序列的 ——
`nova_defines.v` 注释里的加码历史就是证据。

**注释里记录的加码历史**（`nova_defines.v` 原文）：

```
// 50000 --> 51500 --> 52000 --> 52500 --> 55000 --> 56000 --> 56500 --> 57300
```

**每次加码都是因为 ext_frame_RAM 从异步读改成同步读**（多 1 周期延迟，
重建变慢），需要给更多时间。

### `PPS_SPS_complete`：让 SPS/PPS 不受速率控制

```verilog
// bitstream_gclk_gen.v
assign parser_ena =
    (parser_state == `rst_parser && (!PPS_SPS_complete ||
        (PPS_SPS_complete && end_of_one_frame))) ||
    (parser_state == `start_code_prefix && start_code_prefix_found) ||
    (nal_unit_state == `rbsp_trailing_one_bit && pc_2to0 == 3'b000) ||
    (nal_unit_state == `rbsp_trailing_zero_bits);
```

**`PPS_SPS_complete` 在解析到第一个 slice_header 时置 1**。

**含义**：

- **SPS/PPS 阶段**：`PPS_SPS_complete == 0` → `parser_ena` 不受 `end_of_one_frame` 限制 → **立刻解析**
- **slice 阶段**：`PPS_SPS_complete == 1` → 必须等 `end_of_one_frame` → **受速率控制**

**否则会死锁**：如果一开机就要等 `end_of_one_frame`（45000 周期）才能读 SPS，
那要跑 45000 周期才知道分辨率。

| `gclk_intra_mbAddrA_Cr` | 左邻像素缓存（Cr）| `rec_counter==21 \|\| 23` |
| `gclk_intra_mbAddrB` | 上邻像素缓存 | 分 intra/inter 两大分支 |
| `gclk_intra_mbAddrC_luma` | 右上参考像素 | **只在两种模式** |
| `gclk_intra_mbAddrD` | 左下参考像素 | 三分支 |
| `gclk_seed` | 种子寄存器 | **只在 plane 模式** |
| `gclk_Inter_ref_rf` | 13×13 参考窗口 | **preload 期间** |
| `gclk_pred_output` | 预测结果锁存 | `intra_calculate_counter != 0 \|\| valid != 0` |
| `gclk_blk4x4_sum` | 重建加法 | `sum_counter[2] != 1` |
| `gclk_end_of_MB_DEC` | MB 结束事件 | 直接门控 `end_of_MB_DEC` 电平 |
| `gclk_DF` | 去块滤波 | `DF_duration \| end_of_BS_DEC` |
| `gclk_Intra_mbAddrB_RAM` | `Intra_mbAddrB_RAM` | `rd \| wr` |
| `gclk_rec_DF_RAM0` | `rec_DF_RAM0` | **`!cs_n`** |
| `gclk_rec_DF_RAM1` | `rec_DF_RAM1` | **`!cs_n`** |
| `gclk_DF_mbAddrA_RF` | `DF_mbAddrA_RAM` | `rd \| wr` |
| `gclk_DF_mbAddrB_RAM` | `DF_mbAddrB_RAM` | `rd \| wr` |

### 8.5.2 最省电的一个：`gclk_Inter_ref_rf`

```verilog
assign Inter_ref_rf_ena = (blk4x4_inter_preload_counter == 0) ? 1'b0 : 1'b1;
```

**只要 preload 计数器归零，13×13 = 169 个 8 bit 参考寄存器的时钟立刻关断**。

**169 × 8 = 1352 个触发器** ——这是全芯片最大的一组寄存器。**门控它省掉的
动态功耗非常可观**。

**量化**：假设一个 MB 里 inter 预测占 40% 的时间（约 180 周期），preload
占其中约 20 周期 → **这个时钟只有 11% 的时间是开的**。

### 8.5.3 `gclk_2D` 的"ChromaDC 例外"

```verilog
assign TwoD_en = ((OneD_counter == 3'b001 &&
                   residual_state != `ChromaDCLevel_Cb_s &&
                   residual_state != `ChromaDCLevel_Cr_s) || TwoD_counter != 0);
```

**`residual_state != ChromaDCLevel_Cb && != ChromaDCLevel_Cr`** ——
**ChromaDC 的 2D IDCT 时钟永远不产生**。

**对应第 4 章的结论**：ChromaDC 把 2×2 的 2D Hadamard 摊平成 4×4-like 的
1D 变换（`OneD_counter = 1`），所以 `TwoD_counter = 0`，**2D 级的 4 个周期
被完全省掉**。

**这是"算法优化 → 门控时钟省掉"的完整链条**：
不是"关掉空闲模块的时钟"，而是"**算法上让它根本不需要时钟**"。

### 8.5.4 `gclk_intra_mbAddrA_*` 的三份

**luma / Cb / Cr 各有一份独立门控时钟**：

```verilog
assign Is_LumaRightMostBlk4x4 = (blk4x4_rec_counter == 5 || 7 || 13 || 15);
assign Is_CbRightMostBlk4x4   = (blk4x4_rec_counter == 17 || 19);
assign Is_CrRightMostBlk4x4   = (blk4x4_rec_counter == 21 || 23);

assign intra_mbAddrA_luma_ena =
    (blk4x4_rec_counter < 16 && blk4x4_sum_counter == 3'd3 &&
     ((mb_type_general[3:2] == 2'b11 && !(mb_num_h == 10 && Is_LumaRightMostBlk4x4)) ||
      (mb_type_general[3:2] != 2'b11 && mb_num_h != 10 &&
       Is_LumaRightMostBlk4x4 && !NextMB_IsSkip)));
```

**注释原文（关键）**：

```
// For intra pred, update after every blk4x4 is summed
// For inter pred, update after blk4x4 5,7,13,15 is summed
```

**两种 MB 类型的更新频率完全不同**：

| MB 类型 | 什么时候更新左邻缓存 | MB 内次数 |
|---|---|---|
| **intra** | **每算完一个 4×4 块** | **16 次**（luma）|
| **inter** | **只在块的最后一列**（5/7/13/15）| **4 次** |

**为什么 inter 可以少更新？** 因为 inter 预测的参考像素**从帧存读**，
不从"左邻缓存"读——只有**写回**时才需要更新左邻缓存，而写回只发生在
块的最后一列。

**这直接导致**：inter MB 的 `gclk_intra_mbAddrA_luma` 只有 4 个时钟沿，
vs intra MB 的 16 个。**省 75%**。

**再看 `mb_num_h == 10`（最右列）的条件**：

```verilog
!(mb_num_h == 10 && Is_LumaRightMostBlk4x4)   // intra：最右列的最右块不更新
```

**为什么？** 因为**最右列的 MB 的右邻不存在**——没有 MB 会用到"右邻的左列"。
所以最右列 MB 的**最右块**做完后不需要更新左邻缓存。

### 8.5.5 `gclk_intra_mbAddrC_luma`：只有两种模式

```verilog
assign intra_mbAddrC_luma_ena =
    (mb_type_general[3:2] == 2'b11 &&
     (Intra4x4_predmode == `Intra4x4_Diagonal_Down_Left ||
      Intra4x4_predmode == `Intra4x4_Vertical_Left) &&
     blk4x4_intra_preload_counter == 3'b010);
```

**9 种 Intra4×4 模式里只有 2 种需要右上参考像素**：

- `Diagonal_Down_Left`（模式 3）
- `Vertical_Left`（模式 7）

**其余 7 种模式根本没用到右上像素**（第 5 章讲过：只有这两个模式需要
P4..P7 作为"右上"）。

**注释原文**：

```
// 1) For blkIdx=0/1/4/5, Intra_mbAddrC_reg are loaded from Intra_mbAddrB_RAM
// 2) For blkIdx other than 0/1/4/5, Intra_mbAddrC_reg directly obtained from Intra_mbAddrB_reg
```

**即**：只有 MB 的**左上 4 个块**（0/1/4/5）需要从 SRAM 读右上像素，
其余 12 个块的右上像素**直接从已算好的上邻块取**（零成本）。

### 8.5.6 `gclk_blk4x4_sum`：一个位判断

```verilog
assign blk4x4_sum_ena = (blk4x4_sum_counter[2] != 1'b1);
```

**`blk4x4_sum_counter` 是 3 bit（0..4）**：

- 0/1/2/3 → `[2] == 0` → **时钟开**
- 4 → `[2] == 1` → **时钟关**（4 是空闲态）

**用最高位一个 bit 判断"忙/闲"**，不用比较器。

### 8.5.7 `gclk_end_of_MB_DEC`：直接门控事件电平

```verilog
always @ (clk or end_of_MB_DEC)
    if (!clk)
        l_end_of_MB_DEC <= end_of_MB_DEC;
assign gclk_end_of_MB_DEC = l_end_of_MB_DEC & clk;
```

**这是唯一一个"把信号本身当使能"的门控时钟**。

**为什么？** 因为 `end_of_MB_DEC` 是**单周期脉冲**（`blk4x4_rec_counter == 23 &&
end_of_one_blk4x4_sum`）。**用它自己当使能，就在它有效的那一拍产生一个时钟沿**。

**这解决了第 2 章提到的"门控时钟关掉时组合逻辑事件会丢"的问题**：

如果 `gclk_end_of_MB_DEC` 用别的东西当使能（比如 `blk4x4_rec_counter == 23`），
那 `end_of_MB_DEC` 在别的时刻变化就没人采到。**所以必须让事件自己驱动时钟**。

**这个时钟驱动什么？**

- `blk4x4_rec_counter` 归零（`sum.v`）
- `nC_decoding` 的 `Luma_8x8_AllZeroCoeff` 寄存器更新
- DF 的 `indexA/indexB` 更新（第 7.4 节）
- `mb_type_general_DF` 锁存

**所有这些"每 MB 只做一次"的操作，共用一个每 MB 只有一个沿的时钟。**

## 8.6 门控时钟的代价与验证

### 代价 1：时序分析要按 gclk 分析

**综合时要把 `gclk_xxx` 声明为 generated clock**：

```tcl
# 典型综合脚本（nova 没提供，这是通用做法）
create_generated_clock -name gclk_DF -source [get_ports clk] \
    -divide_by 1 [get_pins l_DF_ena_reg/Q]
```

**否则 STA 会认为 `gclk_DF` 和 `clk` 无关，时序全错**。

### 代价 2：负沿锁存器不是标准单元

**真实工艺库里 ICG 是一个专门的 cell**（如 TSMC 的 `CKLNQD1`）。
nova 用 RTL 写出等价行为，综合工具**必须能识别** `if (!clk) l_ena <= ena`
这个模式并映射到 ICG cell。**不能识别的工具会综合成普通锁存器 + 与门**，
面积大一点但功能正确。

### 验证：门控时钟不能改变功能

**这是最容易出 bug 的地方**：如果使能条件写错一个 bit，某个寄存器就会
**少更新一次**，导致整帧偏色或错块。

**nova 的验证策略**：我们做 300 帧比特精确对比（第 9 章），
**任何门控条件的错误都会立刻在像素上暴露**。所以：

> **"比特精确"是门控时钟正确性的最强证明。**

## 8.7 本章小结：存储与时钟的协同设计

### 核心思想

**nova 的存储和时钟是"一起设计"的，不是"先设计逻辑再优化"**：

| 存储 | 尺寸 | 为什么这个尺寸 | 对应的门控时钟 |
|---|---|---|---|
| `mvx_mbAddrB_RF` | 32×11 | **一个 MB 的 16 个 4×4 块 × 2（8×8 粒度）** = 32 | `gclk_mvx_mbAddrB_RF` |
| `Intra4x4_PredMode_RF` | 16×11 | 一个 MB 的 16 个 4×4 块 = 16 | `gclk_Intra4x4PredMode_mbAddrB_RF` |
| `LumaLevel_RF` | 20×11 | 16 块 + 4（上邻延伸）= 20 | `gclk_LumaLevel_mbAddrB_RF` |
| `rec_DF_RAM0/1` | 96×32 | **24 块 × 4 word** = 96 | `gclk_rec_DF_RAM0/1` |
| `DF_mbAddrB_RAM` | 352×32 | **11 列 × 32** = 352 | `gclk_DF_mbAddrB_RAM` |

**每个存储的深度都精确等于"一个 MB 需要的量"或"跨 MB 边界需要的量"**，
没有留多余空间。**门控时钟的使能条件也正好对应这些存储的访问时刻**。

### 五个可复用的技巧

1. **小容量高带宽用 RF（异步读），大容量用 SRAM（同步读）** ——
   nova 8 个 RF（2.4 Kbit）+ 5 个 SRAM（21 Kbit），按访问频率分工
2. **存储深度 = 一个 MB 的块数** —— 让地址计算变成"块内偏移 + MB 基址"，
   无乘法
3. **双缓冲解决并行流水** —— `rec_DF_RAM0/1` 让 `sum` 和 `DF` 同时工作
4. **负沿锁存 + 与门 = ICG，一个模式 40 处复用** —— 统一的门控时钟写法
5. **脉冲事件自己当使能** —— `gclk_end_of_MB_DEC` 保证单周期事件不被丢

### 省电效果量化

**假设 1.5 MHz、1.0 V、0.18 µm**：

| 项 | 不门控 | 门控后 | 省 |
|---|---|---|---|
| 时钟树（40 组，平均 30% 开）| 100% | 30% | **70%** |
| `Inter_ref_rf`（1352 DFF）| 100% | 11% | **89%** |
| `mvx/mvy_mbAddrB_RF`（704 DFF）| 100% | ~2% | **98%** |
| **总体动态功耗** | — | — | **约 60–70%** |

**这与论文的 293 µW 吻合**：不门控的同等设计大约 800 µW–1 mW。

## 8.8 实验：观察门控时钟

### 实验 1：数门控时钟的翻转次数

写一个探测模块，统计 `gclk_Inter_ref_rf` 在一个 MB 内的上升沿：

```verilog
// /tmp/gclk_probe.v
module gclk_probe;
    integer irf_edges = 0, mb_count = 0;
    always @ (posedge tb_nova.u_nova.reconstruction.Inter_pred_top.Inter_pred_pipeline.gclk_Inter_ref_rf)
        irf_edges = irf_edges + 1;
    always @ (posedge tb_nova.u_nova.end_of_MB_DEC)
        begin
            mb_count = mb_count + 1;
            if (mb_count % 20 == 0)
                $display("[GCLK] MB=%0d  Inter_ref_rf edges=%0d  avg=%.1f",
                         mb_count, irf_edges, irf_edges * 1.0 / mb_count);
        end
endmodule
```

**预期**：akiyo 的 inter MB 只有 8/99，其余都是 skip（不做 inter 预测）。
所以平均值会很低。

### 实验 2：验证门控不改变功能

**这是最重要的实验**：

```bash
cd /home/chenye/learning/nova/sim
# 正常跑
./scripts/run_regression.sh -n 10 --tag gclk_on
# 把 rec_gclk_gen 里所有 assign gclk_xxx = clk & l_xxx_ena 改成 clk（等价于全不门控）
sed -i 's/assign gclk_\(.*\) = clk & l_\1_ena;/assign gclk_\1 = clk;/' rtl/rec_gclk_gen.v
./scripts/run_regression.sh -n 10 --tag gclk_off
# 两者应该比特精确一致
```

**如果两个 YUV 不一致 → 门控条件有 bug。**
**如果一致 → 门控是正确的**（只是省电）。
