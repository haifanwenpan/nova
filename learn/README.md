## 三句话概括这个 IP

1. **它不是通用解码器，而是一篇论文的硅验证载体。** 作者 Ke Xu 的博士论文
   *Power-efficient Design Methodology for Video Decoding* 里的每一个"低功耗技巧"
   在 RTL 里都能找到对应实现：Gray 码状态机、分层 leading-one 检测、latch 时钟门控、
   移位代替乘法、查表代替除法。读这个 IP 的最大收获不是"学会 H.264"，
   而是"学会在 RTL 里怎么省"。

2. **它的性能数字非常干净，可以复现。** 规格书说去块滤波 204 cycles/MB，
   我们在 iverilog 里实测 **209 cycles/MB**（多出的 5 拍是流水线填充/排空）。
   规格书说 QCIF@30fps 只需 1.5MHz，我们跑 300 帧实测均值 **49954 cycles/帧**，
   49954 × 30 = **1.50 MHz** —— 与规格书精确吻合。
   更值得玩味的是：**MB 级速度是 330 cycles/MB，与 `freq_ctrl` 完全无关**，
   而 DF 占了其中 63% —— 这解释了作者为什么专门为去块滤波写一篇论文。

3. **它只实现了 Baseline 的一个子集，而且卡得很死。** 最致命的限制是
   **SPS 解析器是硬连线的固定字段序列**，要求 `pic_order_cnt_type == 0`。
   现代 x264 即使加 `-profile:v baseline` 也会输出 `poc_type=2`，
   于是 nova 会把整个 SPS 解析错位，宽高都读错，一帧都解不出来。
   **详见第 10 章**，这是复用这个 IP 时第一个会撞的墙。

## 已验证的事实（本文档的可信度来源）

| 验证项 | 方法 | 结果 |
|---|---|---|
| 功能正确性 | iverilog 跑 300 帧 akiyo QCIF，与 ffmpeg 逐像素比对 | **300/300 帧比特精确，PSNR = ∞、maxdiff = 0** |
| 去块滤波周期 | 探针测 `DF_duration` 高电平宽度 | **209 cycles/MB**（论文 204） |
| 整帧周期 | testbench 统计（300 帧） | **49954 cycles/帧**（49954 × 30 = 1.50 MHz） |
| 变频档位 | `freq_ctrl[1:0]` 四档实测（14 帧稳态）| **45009 / 50009 / 57046 / 68839 cycles/帧** |
| MB 级速度 | 探针测帧内 MB 间隔 | **330 cycles/MB**，与 `freq_ctrl` 完全无关 |
| MB 类型差异 | 按 `mb_type_general` 分类统计 | skip **326** / 16×16 **422** / P_8x8 **515** |
| 速率控制下限 | 二分法改 `cycles_per_frame0` | akiyo 真实需求 **42100**（出厂 45000，余量 6.4%）|
| 去块滤波效果 | 关掉 DF 对比 | PSNR 从 ∞ 降到 **46.35 dB**（akiyo 静止序列） |
| x264 兼容性 | 用 ffmpeg 生成 baseline 码流 | **FAIL，一帧都解不出**（根因见第 10 章） |

> 注：前 299 帧由 `slice_header_s6` 主路径吐出，第 300 帧（末帧，后面没有下一个
> slice header）由 testbench 的"码流耗尽"分支兜底吐出 —— 两者都是已完整重建的帧。
> 末帧问题折腾了三个版本的修复，来龙去脉见第 9.2 节。

## 目录速查

- `src/` —— 原始 RTL（**不要直接改**，仿真用 `sim/rtl/` 的副本）
- `doc/nova_spec.doc` —— 规格书（Word 97 格式，4 张架构图是嵌入的 Visio 对象）
- `test/bitstream/akiyo300_1ref.txt` —— 随 IP 附带的 JM94 编码码流（300 帧 QCIF）
- `learn/doc_extract/nova_spec.txt` —— 规格书正文的纯文本提取结果（195 行）
- `sim/` —— 我们建立的 iverilog 仿真环境（见第 9 章）
  - `sim/rtl/` —— `src/` 的副本 + 两处位宽补丁（**仿真用这个，不改 `src/`**）
  - `sim/tb/tb_nova.v` —— 自写 testbench，直接输出标准 YUV420p
  - `sim/scripts/run_regression.sh` —— 一键六步回归（准备码流 → ffmpeg 参考 → 编译 → 仿真 → 逐像素比对 → 帧数校验）
